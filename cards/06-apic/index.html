APIC：粒子法里的数值耗散，很多时候来自“信息在表示转换时被丢掉”

Aug 19, 2026
阅读时长: 5 分钟

APIC：粒子法里的数值耗散，很多时候来自“信息在表示转换时被丢掉”

主题：Affine Particle-In-Cell（APIC）与粒子—网格传递
领域：MPM × 流体/软体动力学 × 数值方法 × 物理引擎
推荐阅读时间：约 8 分钟

今天讲 APIC，因为它揭示了一个很容易被忽略的求解器问题：

\[ \boxed{\text{数值耗散不一定来自时间积分或材料模型，也可能来自状态表示之间的信息损失。}} \]

APIC 由 Jiang、Schroeder、Selle、Teran 和 Stomakhin 在 SIGGRAPH 2015 提出。作者给出的出发点非常明确：传统 PIC 稳定但耗散严重；FLIP 为减少耗散保留更多粒子信息，却更容易产生噪声和不稳定；APIC 希望在两者之间取得更好的结构性折中。

这件事对做求解器尤其值得理解，因为 APIC 改的并非 constitutive model，也没有引入更高阶时间积分器。

它只改变：

\[ \boxed{\text{particle}\leftrightarrow\text{grid}} \]

之间到底传递多少信息。

1. 先理解 MPM/PIC 为什么需要“来回搬数据”

MPM 一类方法有两套表示：

\[ \boxed{\text{Particles}} \]

负责携带材料：

  • 质量；
  • 位置；
  • 速度；
  • 形变梯度 \(F\)；
  • 应力；
  • 材料参数；

而临时背景网格：

\[ \boxed{\text{Grid}} \]

负责：

  • 汇聚质量；
  • 计算动量；
  • 计算力；
  • 处理接触；
  • 求解运动。

一个典型时间步近似是：

\[ \text{Particles} \xrightarrow{\mathrm{P2G}} \text{Grid} \xrightarrow{\text{physics}} \text{Grid} \xrightarrow{\mathrm{G2P}} \text{Particles}. \]

这正是 hybrid Lagrangian/Eulerian 方法的基本结构：粒子便于追踪材料输运和大拓扑变化，Eulerian 背景网格适合计算机械力和碰撞。

于是出现了一个非常关键的问题：

粒子上的连续速度场，被映射到网格，再映射回来以后，还剩下多少原始运动信息？

APIC 就是在解决这个问题。

2. PIC 的问题：一个粒子只记住一个速度

传统 PIC 中，每个粒子基本只携带：

\[ (x_p,v_p). \]

也就是说，对粒子附近的速度场，它采用：

\[ v(x)\approx v_p. \]

这是一个零阶局部模型：

\[ \boxed{\text{局部速度场是常数}} \]

P2G 时：

\[ m_i=\sum_p w_{ip}m_p, \]

[ m_i v_i

\sum_p w_{ip}m_pv_p. ]

网格算完之后，再插值回来：

[ v_p^{n+1}

\sum_iw_{ip}v_i^{n+1}. ]

问题就在这里。

假设真实局部运动是一个旋转：

\[ v(x)=\omega\times(x-x_c). \]

在空间不同位置：

\[ v(x_1)\neq v(x_2). \]

但传统 PIC 的一个粒子只留下一个：

\[ v_p. \]

局部速度梯度：

\[ \nabla v \]

就没有被粒子显式保存。

因此：

\[ \text{particle} \rightarrow \text{grid} \rightarrow \text{particle} \]

实际上包含一次信息压缩。

APIC 原论文把 PIC 耗散的核心来源直接归结为这种 transfer 中的信息损失。

3. 一个直观例子：旋转的刚体块

考虑一团材料纯刚体旋转。

真实速度：

\[ v(x)=v_c+\omega\times(x-x_c). \]

这个速度场不是常数，而是一个线性/仿射速度场。

可以写成：

\[ v(x)=v_c+C(x-x_c), \]

其中对于纯旋转：

\[ C= [\omega]_\times. \]

现在让 PIC 反复执行：

\[ P2G\rightarrow G2P. \]

粒子只记录：

\[ v_p, \]

于是旋转速度场中的空间变化被不断重新插值和平均。

结果表现为：

\[ \omega\downarrow \]

即系统逐渐丢失旋转运动。

宏观上你看到的是：

\[ \boxed{\text{numerical dissipation}} \]

但微观原因实际上是：

\[ \boxed{\text{representation loss}} \]

而不一定是阻尼项。

这正是 APIC 最值得记住的洞察。

4. FLIP 为什么没有那么耗散？

FLIP 采取另一种做法。

它不简单把网格的新速度覆盖粒子：

[ v_p^{n+1}

\sum_i w_{ip}v_i^{n+1}. ]

而是把网格上的速度增量传给粒子：

[ v_p^{n+1}

v_p^n + \sum_iw_{ip} \left( v_i^{n+1}-v_i^n \right). ]

所以粒子原本拥有的信息：

\[ v_p^n \]

不会被每步重新投影掉。

这就是为什么 FLIP 通常耗散更小。

但代价也随之而来。

粒子可以保存一些网格无法解析的 velocity modes；这些信息不会被 PIC 那样的投影过程过滤掉，于是可能不断积累。APIC 后续的角动量守恒分析明确指出，FLIP 缺少 PIC 的 filtering property，因此可能积累粒子速度模式并出现数值不稳定。

因此可以把两者粗略理解为：

\[ \boxed{ \text{PIC：过滤太强} } \]\[ \boxed{ \text{FLIP：过滤太弱} } \]

这比简单理解成“PIC 有阻尼、FLIP 没阻尼”准确得多。

5. APIC 的核心：粒子多保存一个局部速度梯度

APIC 的突破其实很简单。

传统粒子：

\[ (x_p,v_p) \]

升级成：

\[ \boxed{(x_p,v_p,C_p)} \]

其中：

\[ C_p \]

描述粒子附近的 affine velocity field：

[ \boxed{ v(x)

v_p+ C_p(x-x_p) } ]

于是传统 PIC 的局部表示：

\[ v(x)\approx v_p \]

从零阶升级为：

\[ v(x)\approx v_p+C_p(x-x_p). \]

这意味着一个粒子不只知道：

“我在往哪里移动。”

它还知道：

“我附近的速度场正在怎样变化。”

例如：

平移

\[ C_p=0. \]

刚体旋转

\[ C_p=[\omega]_\times. \]

剪切

可能有：

\[ C_p= \begin{bmatrix} 0 & \gamma\\ 0 & 0 \end{bmatrix}. \]

拉伸

可能有：

\[ C_p= \begin{bmatrix} a&0\\ 0&b \end{bmatrix}. \]

因此一个 APIC particle 实际上带着一个“小型局部速度场”。

这正是作者所谓 locally affine rather than locally constant velocity representation。

6. P2G 因此发生了本质变化

传统 PIC：

[ m_i v_i

\sum_p w_{ip}m_pv_p. ]

APIC 则近似变成：

[ m_i v_i

\sum_p w_{ip}m_p \left[ v_p+C_p(x_i-x_p) \right]. ]

注意后面的：

\[ \boxed{ C_p(x_i-x_p) } \]

就是 APIC 多出来的信息。

假设一个粒子处于旋转速度场。

如果只传：

\[ v_p, \]

网格不知道该粒子周围存在旋转。

但 APIC 会告诉相邻节点：

\[ v_i \approx v_p+C_p(x_i-x_p). \]

于是网格得到的不是一块常值速度：

1

→ → →
→ → →
→ → →

而能够重构类似：

1

↖ ↑ ↗
← • →
↙ ↓ ↘

这样的局部变化。

所以：

\[ P2G \]

过程中不再把 affine velocity modes 全部压扁掉。

7. 为什么它还能解决角动量问题？

这是 APIC 更深的一层。

一个粒子的总运动并不只有：

\[ m_pv_p \]

对应的平移动量。

局部 affine field：

\[ C_p \]

还包含粒子附近的旋转信息。

因此 APIC 在 particle-grid transfer 中可以同时维护：

\[ \boxed{\text{linear momentum}} \]

以及：

\[ \boxed{\text{angular momentum}}. \]

后续严格分析证明 APIC transfer 可以精确保持线动量和角动量；结合 midpoint rule 更新 grid momentum 时，完整步骤也可以做到两者的精确守恒。

这解释了一个非常有价值的现象：

APIC 的低耗散不是靠“少一点 damping parameter”获得的。

它来自：

\[ \boxed{\text{状态空间变丰富}} \]

使原来无法表达的角动量信息有地方存储。

8. 这和 FEM 中的“阶次”其实有相似思想

这里有一个很适合迁移的理解。

传统 PIC particle：

\[ v(x)\approx v_p \]

是局部：

\[ P_0 \]

式描述。

APIC：

\[ v(x)\approx v_p+C_p(x-x_p) \]

加入一阶项：

\[ P_1. \]

于是一个自然的问题是：

为什么停在 affine？

完全可以继续：

[ v(x)

v_p+ C_p(x-x_p) + Q_p:(x-x_p)^2+\cdots ]

这正是后来的 PolyPIC（Polynomial Particle-In-Cell） 思路：进一步丰富粒子携带的局部速度场表示。相关工作明确把 APIC 看成粒子局部模式扩展的一部分。

所以：

\[ \boxed{ \text{PIC} \rightarrow \text{APIC} \rightarrow \text{PolyPIC} } \]

其实可以理解为：

\[ \boxed{ \text{particle velocity basis enrichment} } \]

与有限元里：

\[ P_1\rightarrow P_2\rightarrow P_3 \]

提高 approximation space 的思想有相似性。

9. MLS-MPM 又把 APIC 推进了一步

2018 年 Hu 等提出 Moving Least Squares MPM（MLS-MPM）。

这篇工作很重要，因为它说明 APIC 不只是一个经验性的 transfer trick。

从 Moving Least Squares 的角度出发，可以自然推导出 APIC，甚至进一步得到 PolyPIC，并让 particle-grid transfer 与一种 Galerkin-style weak-form discretization 相一致。

这意味着：

\[ \boxed{ \text{APIC transfer} } \]

可以被理解成一种：

\[ \boxed{ \text{局部函数重构} } \]

问题。

已知粒子附近的数据，我们希望找：

\[ v(x)=v_p+C_p(x-x_p) \]

这样的局部函数，使它尽可能好地解释附近网格/粒子信息。

于是 APIC 与：

  • moving least squares；
  • FEM shape functions；
  • Galerkin weak form；
  • particle-grid projection

开始进入同一个数学框架。

MLS-MPM 还给出一种新的 stress divergence discretization，论文报告这一结构使其 MPM 实现获得约 2× 的计算加速，并进一步支持 cutting、动态开放边界及双向刚体耦合。

10. APIC 有一个容易混淆的点：\(C_p\) 不是材料形变梯度 \(F_p\)

这是实现 MPM 时特别容易混在一起的两个量。

材料形变梯度：

[ F_p

\frac{\partial x}{\partial X} ]

描述：

\[ \boxed{\text{material deformation}} \]

并进入 constitutive model：

\[ P=P(F). \]

例如 Neo-Hookean：

[ \Psi(F)

\frac{\mu}{2} (\operatorname{tr}(F^TF)-d) -\mu\ln J + \frac{\lambda}{2}(\ln J)^2. ]

而 APIC：

\[ C_p \]

描述：

\[ \boxed{\text{local velocity variation}} \]

近似：

\[ C_p\approx\nabla v. \]

二者有联系：

[ \dot F

(\nabla v)F, ]

但职责不同：

\[ \boxed{ F_p:\ \text{材料状态} } \]\[ \boxed{ C_p:\ \text{传输状态} } \]

这个区分非常重要。

11. 它真正揭示的求解器设计原则

现在把 APIC 从 MPM 中抽出来。

假设一个模拟器不断在：

\[ A\rightarrow B\rightarrow A \]

两个 representation 之间转换。

如果：

\[ A \]

可以描述 100 个自由度的信息，而：

\[ B \]

只能表示其中 70 个，那么即使两边：

  • 时间积分完全正确；
  • 材料模型完全正确；
  • force calculation 完全正确，

每次：

\[ A\rightarrow B\rightarrow A \]

依然会发生：

\[ \boxed{\text{information loss}} \]

表现出来可能就是：

  • damping；
  • smoothing；
  • phase error；
  • angular momentum loss；
  • aliasing。

这是 APIC 最值得迁移到其他求解器上的思想。

12. 这与你熟悉的 XPBD/软体问题其实有直接联系

考虑：

\[ x \rightarrow \text{constraint solve} \rightarrow x' \]

然后速度通过：

[ v^{n+1}

\frac{x^{n+1}-x^n}{h} ]

重建。

你实际上也在进行一种：

\[ \boxed{ \text{state representation transfer} } \]

原本系统有：

\[ (x^n,v^n) \]

两个状态；

position solve 改变：

\[ x, \]

最后又从位置差重新构造：

\[ v. \]

如果 constraint projection 中某种运动模式无法被保持，那么：

\[ v^n \]

中原来存在的信息可能在：

\[ x\rightarrow v \]

重建过程中消失。

于是你看到：

\[ KE\downarrow. \]

这时候继续问：

“哪个 damping parameter 太大？”

可能找不到答案。

更应该问：

\[ \boxed{ \text{整个时间步的不同 representation 是否携带相同的信息空间？} } \]

这就是 APIC 能迁移到 XPBD/物理求解器设计上的真正价值。

13. 一个很好的工程测试：Transfer Null Test

如果以后实现 MPM/APIC，我非常建议单独测试 transfer，而不要直接上完整材料仿真。

设置：

\[ f_{\rm internal}=0, \]\[ f_{\rm external}=0, \]

不进行 constitutive update。

只不断：

\[ P2G\rightarrow G2P. \]

然后分别初始化：

Test A：常速度场

\[ v(x)=c \]

检查：

\[ \Delta P. \]

Test B：刚体旋转

\[ v(x)=\omega\times x \]

检查：

\[ \Delta L. \]

Test C：线性速度场

\[ v(x)=Ax+b \]

检查：

\[ \|v^{(k)}-v^{(0)}\|. \]

如果一个方法经过：

\[ 100 \]

次纯 transfer 后，旋转逐渐停下来，那么你已经证明：

\[ \boxed{\text{耗散来自 transfer}} \]

而与：

  • constitutive model；
  • timestep；
  • contact；
  • FEM stress

全部无关。

这是一种非常有效的模块化诊断思维。

14. APIC 的局限

APIC 并没有消灭 MPM 的其他误差来源。

它主要处理的是：

\[ \boxed{\text{particle-grid velocity transfer}} \]

这一层。

MPM 仍然可能受到：

  • interpolation kernel；
  • grid crossing；
  • quadrature error；
  • constitutive stiffness；
  • contact；
  • time integration；
  • particle distribution

等因素影响。

例如近年来对 MPM 的研究仍在处理 cell-crossing error 和 transfer kernel 连续性问题。2024 年提出的 CK-MPM 就专门针对传统 MPM kernel 的稳定性、扩散和计算支撑域之间的权衡，并明确保持与 APIC/MLS-MPM 的兼容。

因此 APIC 在知识体系中的位置更准确地说是：

\[ \boxed{ \text{constitutive law} \quad\vert\quad \underbrace{\textbf{particle-grid transfer}}_{\text{APIC}} \quad\vert\quad \text{grid solver} } \]

它解决的是中间这一层，而不是完整 MPM 的所有数值问题。

今天值得留下的一句话

APIC 最值得记住的其实不是：

[ v_i

\sum_p w_{ip} \left[v_p+C_p(x_i-x_p)\right]. ]

而是：

\[ \boxed{ \text{如果一个数值方法不断丢失某种物理量， 先检查算法内部的 representation 是否有能力表示它。} } \]

PIC 的问题并不只是“参数太耗散”。

它原来的粒子状态：

\[ (x_p,v_p) \]

根本没有足够的局部自由度来携带完整的一阶速度结构。

APIC 的解决方案于是非常干净：

\[ \boxed{ \text{不要补偿丢掉的信息， 让状态表示从一开始就能够携带它。} } \]

这是一种比调 damping、clamp 或 blending coefficient 更深一层的求解器设计思想。

  1. Jiang et al., The Affine Particle-In-Cell Method, SIGGRAPH 2015。建议首先看 Walt Disney Animation 官方论文页；摘要已经非常清楚地给出了 PIC → FLIP → APIC 的问题链，以及“information loss 导致 numerical dissipation”这一核心观点。

  2. Jiang, Schroeder & Teran, An Angular Momentum Conserving Affine-Particle-In-Cell Method, Journal of Computational Physics, 2017。如果想真正理解 APIC 为什么能保持线动量/角动量，以及 FLIP 为什么可能积累粒子速度模式，这篇比 SIGGRAPH 版本更适合深入推导。

  3. Hu et al., A Moving Least Squares Material Point Method with Displacement Discontinuity and Two-Way Rigid Body Coupling, SIGGRAPH 2018。它把 APIC 放进 MLS/Galerkin 视角，并有作者提供的论文、视频和代码入口；项目页还链接了非常短的 88-line MLS-MPM 实现，适合直接看工程结构。

  4. 如果想亲手实现一个最小版本，Stanford CS348C 曾把 APIC 做成课程编程任务，从现有 2D PIC/FLIP 框架扩展到 APIC，是很好的实现切入口。
