Matrix-Free FEM：为什么“不组装刚度矩阵”反而可能让有限元更快？

Sep 23, 2026
阅读时长: 5 分钟

主题：Matrix-Free / Partial Assembly 与 Sum Factorization
领域：有限元 × GPU/HPC × 求解器架构
推荐阅读时间：约 8 分钟

今天选一个和前几张 PD、AVI、DWR 都不同，但对“以后自己写真正高性能求解器”很关键的概念：Matrix-Free FEM（无矩阵有限元）。

传统有限元的标准流程几乎已经形成条件反射：

\[\text{单元积分}\rightarrow K_e \rightarrow\text{组装全局 }K \rightarrow Ku.\]

Matrix-Free 方法却问：

\[\boxed{\text{如果最终只是想计算 }y=Ku,\text{ 为什么一定要先把 }K\text{ 存下来？}}\]

它直接从弱形式重新计算 \(Ku\)，甚至在高阶有限元和 GPU 上，比读取已经组装好的稀疏矩阵更快。

这背后的原因很值得理解：现代计算机越来越经常不是“算不动”，而是“搬不动数据”。

1. 传统 FEM 真正在存什么？

以线性弹性为例：

\[Ku=f.\]

传统 assembly：

\[K=\sum_e R_e^TK_eR_e.\]

其中 \(R_e\) 从全局自由度抽取单元自由度。

之后迭代求解器反复计算：

\[y=Kx.\]

看起来非常合理。

但注意 sparse matrix-vector multiplication（SpMV）做了什么：

1
2
3
4
5

读取 K 的非零值
读取列索引
读取 x
做少量乘加
写回 y

每读取一个矩阵元素，往往只对应：

\[1\text{ multiply}+1\text{ add}.\]

因此计算强度：

\[\boxed{ I=\frac{\text{FLOPs}}{\text{bytes moved}} }\]

很低。

现代 CPU/GPU 的浮点吞吐增长速度远快于内存带宽，于是 SpMV 很容易成为：

\[\boxed{\text{memory-bandwidth bound}.}\]

Kronbichler 与 Kormann 对 matrix-free DG 的性能分析甚至发现，完整 operator evaluation 的性能经常已经接近机器可用 memory bandwidth 的极限。

2. Matrix-Free 做了一件看起来“反效率”的事

不存：

\[K.\]

每次需要：

\[y=Kx\]

时，重新执行有限元积分。

对于一个典型双线性型：

\[a(u,v) = \int_\Omega \nabla v^T D(x)\nabla u\,d\Omega,\]

传统方法先算：

\[K_{ij} = \int_\Omega \nabla N_i^TD\nabla N_j\,d\Omega.\]

Matrix-Free 则直接：

\[x \rightarrow u_h \rightarrow \nabla u_h \rightarrow D\nabla u_h \rightarrow \int\nabla N_i^TD\nabla u_h.\]

于是：

\[\boxed{ Kx\text{ 被重新解释为一次有限元算子评价。} }\]

这意味着更多 FLOPs。

但数据搬运大幅减少。

在现代硬件上：

\[\boxed{\text{多算一点，可能比多读一点更便宜。}}\]

这正是 Matrix-Free 最反直觉也最重要的地方。

3. 更准确地说，有限元算子本来就不是“一块矩阵”

MFEM 官方 Partial Assembly 文档 把有限元算子分解得非常漂亮：

\[\boxed{ A=P^TG^TB^TDBG P. }\]

这里可以粗略理解为：

\[P:\text{全局/并行自由度映射}\]\[G:\text{global DOF}\rightarrow\text{element DOF}\]\[B:\text{element DOF}\rightarrow\text{quadrature point}\]\[D:\text{积分点上的几何与物理作用}.\]

所以一个 FEM operator 实际上是：

\[\boxed{ \text{global} \rightarrow \text{element} \rightarrow \text{quadrature} \rightarrow \text{physics} \rightarrow \text{element} \rightarrow \text{global}. }\]

全局 sparse matrix \(A\) 只是把整个计算过程提前展开并缓存后的结果。

4. Partial Assembly 是中间路线

这里有一个很重要的层次：

\[\text{Full Assembly}\]

存整个：

\[A.\]

Element Assembly：

存：

\[K_e.\]

Partial Assembly：

只存积分点上的：

\[D.\]

Matrix-Free：

连更多中间量也动态计算。

所以你可以把 assembly 看成一条连续谱：

\[\boxed{ \text{更多预计算/更多内存} \longleftrightarrow \text{更少存储/更多在线计算}. }\]

MFEM 当前明确提供 FULL、ELEMENT、PARTIAL 等不同 assembly level；其 partial assembly 的核心就是只保存 \(D\) 或其一部分，而把 \(P,G,B\) 等操作在线执行。

这其实与昨天 PD 的思想形成一个很漂亮的反差：

PD：

\[\boxed{\text{尽量预计算固定结构}}\]

Matrix-Free：

\[\boxed{\text{当预计算结果太大时，宁愿重算}}\]

两者并不矛盾。

真正原则是：

\[\boxed{\text{缓存那些“重算比搬运贵”的东西。}}\]

5. 但如果每次都老老实实算高阶 FEM，计算量不会爆炸吗？

会。

所以 Matrix-Free 高阶 FEM 的另一个核心技术叫：

\[\boxed{\text{Sum Factorization}.}\]

考虑三维六面体高阶单元。

每个方向有：

\[p+1\]

个基函数，因此单元自由度：

\[n\sim(p+1)^3.\]

如果直接计算三维插值：

\[u(q_x,q_y,q_z) = \sum_{i,j,k} B_{q_xi}B_{q_yj}B_{q_zk}u_{ijk},\]

这是一个巨大的三维求和。

但由于六面体基函数是 tensor product：

\[N_{ijk}(x,y,z) = N_i(x)N_j(y)N_k(z),\]

可以分三次一维 contraction。

先：

\[v_{q_xjk} = \sum_iB_{q_xi}u_{ijk},\]

再：

\[w_{q_xq_yk} = \sum_jB_{q_yj}v_{q_xjk},\]

最后：

\[u_{q_xq_yq_z} = \sum_kB_{q_zk}w_{q_xq_yk}.\]

这就是 sum factorization。

6. 它改变了高阶 FEM 的复杂度

三维情况下，直接 dense element operation 的复杂度大致会随：

\[O(p^6)\]

增长。

利用 tensor-product sum factorization 后，可降到大约：

\[\boxed{O(p^4)}.\]

这两个幂次的差距在：

\[p=8,\;10,\;12\]

时已经非常巨大。

所以：

\[\boxed{ \text{Matrix-Free} + \text{Sum Factorization} }\]

才真正构成现代 high-order FEM 的高性能组合。

Kronbichler 与 Kormann 的工作正是系统研究这种 matrix-free + sum-factorization operator evaluation，并展示经过向量化的一维 tensor kernels 可以达到很高的 CPU 算术吞吐。

7. 一个直观类比

查看完整推导与细节

假设你每天需要：

\[f(x)=Ax.\]

传统 sparse FEM 的思路相当于：

把一个复杂食谱的所有可能中间结果做完，装进巨大冰箱，以后每次拿出来。

Matrix-Free：

只保存原料和非常紧凑的配方，需要时现场做。

旧机器：

\[\text{做饭慢，冰箱读取快}\]

于是缓存占优。

现代 GPU：

\[\boxed{\text{“做饭”极快，但从显存搬东西相对昂贵}}\]

于是现场重算越来越划算。

这也是为什么 MFEM 官方明确指出 Partial Assembly 对 GPU 尤其重要：高阶 fully assembled matrix 同时要求大量存储和大量数据传输。

8. 这会产生一个很重要的 Roofline 视角

查看完整推导与细节

性能不应该只看 FLOPs。

定义 arithmetic intensity：

\[I= \frac{\text{FLOPs}}{\text{Byte}}.\]

硬件理论性能近似受：

\[P \le \min ( P_{\rm peak}, I B_{\rm memory} )\]

约束。

这就是经典 Roofline 思想。

如果 sparse matvec：

\[I\ll1,\]

即使 GPU 有：

\[50\text{ TFLOP/s},\]

也根本吃不到这些算力。

Matrix-Free 通过“重新计算”提高：

\[I.\]

所以有一个很值得记住的 HPC 规律：

\[\boxed{ \text{减少 FLOPs} \neq \text{提高性能}. }\]

有时候应该主动：

\[\boxed{\text{用 FLOPs 换 memory traffic}.}\]

9. 这对 GPU 求解器架构特别重要

查看完整推导与细节

Matrix-Free 的典型 kernel 很适合 GPU：

  1. gather element DOFs；
  2. tensor interpolation；
  3. quadrature-point physics；
  4. tensor integration；
  5. scatter。

积分点上的：

\[D(q)\]

通常彼此独立。

因此：

\[\boxed{\text{quadrature physics 天然数据并行}.}\]

而 \(B\) 的 tensor contraction 又可以做：

  • SIMD；
  • warp-level parallelism；
  • shared-memory reuse。

这也是 MFEM、libCEED、deal.II 等现代高阶 FEM 软件都高度重视 matrix-free operator decomposition 的原因。CEED 甚至专门定义 Bakeoff Problems 来比较不同库中 mass/Laplace 等高阶算子的性能实现。

10. 那为什么低阶四面体 FEM 不一定值得 Matrix-Free？

查看完整推导与细节

这是一个重要边界。

假设：

\[P_1\]

线性四面体。

每个 tet 只有：

\[4\]

个节点。

单元矩阵很小，计算：

\[K_e\]

本身也不复杂。

此时：

  • tensor-product 结构弱；
  • sum factorization 优势不存在；
  • gather/scatter 成本占比更高。

所以 Matrix-Free 最耀眼的场景通常是：

\[\boxed{\text{高阶 quad/hex tensor-product elements}.}\]

MFEM 当前官方 partial assembly 实现也主要针对 quadrilateral/hexahedral tensor-product elements。

但这并不意味着 simplex 完全做不了。Moxey、Amici 与 Kirby 已展示 triangle、tetrahedron、prism 等 simplex/prismatic 高阶单元也可以获得高效 matrix-free 实现，只是性能结构更复杂。

11. Matrix-Free 最大的问题：预条件器怎么办？

查看完整推导与细节

如果你有：

\[A,\]

可以直接构造：

  • ILU；
  • AMG；
  • sparse approximate inverse。

但 Matrix-Free 中：

\[\boxed{A\text{ 根本不存在。}}\]

Krylov 方法只需要：

\[v\mapsto Av,\]

所以 CG/GMRES 没问题。

但好的 preconditioner：

\[P^{-1}\]

怎么办？

这恰恰是 matrix-free 方法最重要的工程难点之一。

MFEM 的解决路线包括：

  • matrix-free Jacobi；
  • Chebyshev smoother；
  • \(h\)-multigrid；
  • \(p\)-multigrid。

因此一个真正完整的 matrix-free solver 并不是：

\[\boxed{\text{“把矩阵删掉”}}\]

这么简单。

而是：

\[\boxed{ \text{operator evaluation} + \text{matrix-free-friendly preconditioning} }\]

必须一起设计。

12. 这和 Multigrid 的结合尤其漂亮

查看完整推导与细节

高阶问题：

\[p=8.\]

可以构造：

\[p=8 \rightarrow4 \rightarrow2 \rightarrow1.\]

高阶层：

\[\boxed{\text{matrix-free}}\]

负责便宜 operator application。

到了：

\[p=1\]

低阶层，矩阵已经足够小，可以：

\[\boxed{\text{真正 assemble}}\]

然后使用 AMG/direct solver。

于是形成：

\[\boxed{ \text{high order: compute-rich matrix-free} }\]\[\downarrow\]\[\boxed{ \text{low order: matrix-based robust coarse solve}. }\]

这是一种很典型的现代 HPC 思维：

\[\boxed{\text{不同层级不必坚持同一种数据表示。}}\]

13. 对非线性软体 FEM 更有意思

查看完整推导与细节

考虑 Neo-Hookean：

\[P=P(F).\]

传统 Newton FEM：

\[K(x)=\frac{\partial f}{\partial x}.\]

显式形成：

\[K\]

可能非常昂贵。

但 Newton-Krylov 只真正需要：

\[\boxed{K(x)v.}\]

这可以直接通过：

  • analytic directional derivative；
  • automatic differentiation；
  • finite-difference Jacobian-vector product；

得到。

于是：

\[\boxed{ \text{Matrix-Free} + \text{Newton-Krylov} }\]

允许：

\[\boxed{\text{从头到尾不显式形成 tangent stiffness matrix}.}\]

这对复杂 constitutive model、GPU FEM、differentiable simulation 都非常重要。

14. 这里还能和上一张 PD 卡片形成一个很有价值的对照

查看完整推导与细节

PD 的核心优势：

\[\boxed{K\text{ 固定}}\]

所以：

\[K=LL^T\]

一次 factorization，反复使用。

Matrix-Free Newton-Krylov：

\[\boxed{K(x)\text{ 可以不断变化}}\]

但我们根本不存它，只提供：

\[v\rightarrow K(x)v.\]

所以面对 nonlinear elasticity，有两条完全不同的求解器哲学：

\[\boxed{ \text{PD：改变模型结构，让矩阵固定} }\]

与

\[\boxed{ \text{Matrix-Free：接受矩阵变化，但永远不把它实体化}. }\]

两条路线都在避免：

\[\boxed{\text{反复构造巨大 sparse matrix}.}\]

只是解决方式完全不同。

15. 对自研软体求解器最值得迁移的思想

查看完整推导与细节

即使当前使用 XPBD，而不是 FEM，Matrix-Free 的思想仍然非常有价值。

假设系统有：

\[10^6\]

个 tet constraints。

一种设计是提前存大量：

  • constraint Jacobian；
  • local Hessian；
  • stiffness block。

另一种设计：

每次 kernel 内根据：

\[x_i,x_j,x_k,x_l\]

现场重构：

\[F,\quad J,\quad \nabla C.\]

如果重构只需要几十到几百 FLOPs，却能少读取几十字节甚至数百字节，那么 GPU 上后者可能更快。

因此 profiler 不应该只统计：

\[\boxed{\text{FLOPs}.}\]

更应该统计：

\[\boxed{ \text{bytes moved per constraint} }\]

以及：

\[\boxed{ \text{arithmetic intensity}. }\]

这对 GPU physics solver 是一个非常实用的性能视角。

16. 一个值得自己做的小实验

查看完整推导与细节

做一个规则六面体 Poisson 问题。

比较：

A. Full assembly

构造：

\[K\]

然后反复：

\[y=Kx.\]

B. Matrix-free naive

每次重新做 quadrature。

C. Matrix-free + sum factorization

利用 tensor product。

测试：

\[p=1,2,4,6,8.\]

记录：

\[\boxed{\text{DOF/s}}\]\[\boxed{\text{GB/s}}\]\[\boxed{\text{GFLOP/s}}\]

以及：

\[\boxed{\text{bytes/DOF}.}\]

最值得观察的现象很可能是：

低阶时：

\[\text{assembled}\]

并不差。

随着：

\[p\uparrow,\]

matrix-free + sum-factorization 会越来越占优势。

这比只读理论复杂度更容易真正理解高阶 FEM 为什么重新流行起来。

17. 它还给 AI 工程一个很强的迁移原则

查看完整推导与细节

现代 LLM 推理也越来越受：

\[\boxed{\text{memory bandwidth}}\]

限制。

很多 kernel fusion、FlashAttention、activation recomputation，本质上都在做类似交易：

\[\boxed{\text{多做计算，少搬数据}.}\]

所以 Matrix-Free FEM、FlashAttention、checkpoint recomputation 看起来属于完全不同领域，却共享一个现代计算原则：

\[\boxed{ \text{在算力相对便宜、内存流量昂贵的机器上， “避免重复计算”已经不再是无条件正确的优化目标。}\]

这是 Matrix-Free FEM 最值得迁移出去的一层认识。

今天值得留下的一句话

Matrix-Free FEM 最值得记住的并不是：

\[\boxed{\text{“不存刚度矩阵”}.}\]

真正重要的是：

\[\boxed{ \text{矩阵只是一个算子的某种物化形式； 如果物化后的数据比重新执行算子本身更昂贵， 那就没有必要把它物化。} }\]

它在知识体系中的位置可以画成：

\[\text{Weak Form}\]\[\downarrow\]\[\text{Finite Element Operator}\]\[\begin{array}{ccc} \swarrow && \searrow\\ \text{Assembly} && \text{Matrix-Free} \end{array}\]\[\begin{array}{ccc} K\text{ sparse} && P^TG^TB^TDBG P \end{array}\]

而高阶 FEM 再加入：

\[\boxed{\text{tensor product}}\]\[\downarrow\]\[\boxed{\text{sum factorization}}\]

最终得到：

\[\boxed{ \text{Matrix-Free} + \text{Sum Factorization} + \text{Multigrid} }\]

这已经成为现代高性能高阶有限元的一条核心技术路线。

对于以后真正写 GPU 物理求解器，这张卡片最值得留下的工程判断是：

\[\boxed{ \text{看到一个可以预计算并缓存的大数组时， 先不要问“怎么把它存得更紧凑”， 先问“我真的需要存它吗？”} }\]
