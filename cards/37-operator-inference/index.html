Operator Inference：从轨迹数据反推出一个 ROM

Oct 04, 2026
阅读时长: 1 分钟

主题：Operator Inference（OpInf，算子推断）
领域：降阶模型 × 数据驱动动力学 × Scientific ML
阅读时间：约 4–5 分钟

上一张 Hyper-reduction 仍默认你能够深入原始求解器：访问单元、残差、Jacobian，再对它们做降阶。但工程中经常只有一个商业软件或遗留代码：

\[ (\mu,u_0)\longrightarrow \{u(t_1),u(t_2),\ldots,u(t_N)\}, \]

你能得到仿真轨迹，却拿不到内部离散算子。

Operator Inference 要解决的正是这个缺口：保留 projection-based ROM 的数学结构，但通过数据直接识别低维算子。 它最早由 Benjamin Peherstorfer 和 Karen Willcox 系统提出，用于这种“知道物理结构、拿不到内部算子”的 non-intrusive ROM。

1. 它与“训练一个神经网络预测下一帧”有根本区别

考虑高维动力系统

\[ \dot x=Ax+H(x\otimes x)+Bu, \qquad x\in\mathbb R^N. \]

POD 给出

\[ x\approx Vq,\qquad q\in\mathbb R^r. \]

如果拥有原始算子，可以直接 Galerkin 投影：

\[ \dot q = \underbrace{V^TAV}_{\hat A}q + \underbrace{V^TH(V\otimes V)}_{\hat H} (q\otimes q) + \underbrace{V^TB}_{\hat B}u. \]

问题在于商业软件通常不会给你 \(A,H\)。

OpInf 换了一个问题：

既然我知道降阶方程应该长成什么样，为什么不直接从轨迹拟合 \(\hat A,\hat H,\hat B\)？

从高保真轨迹得到

\[ q_k=V^Tx_k,\qquad \dot q_k\approx V^T\dot x_k, \]

然后求

\[ \boxed{ \min_{\hat A,\hat H,\hat B} \sum_k \left\| \dot q_k- \hat A q_k- \hat H(q_k\otimes q_k)- \hat B u_k \right\|^2. } \]

于是一个高维 PDE/FEM 系统的动力学识别，最终变成一个低维线性最小二乘问题。这正是经典 OpInf 的核心。

2. 最关键的思想：学“方程”，而不是学“轨迹”

假设训练数据覆盖

\[ 0纯 trajectory fitting 很容易学成：

\[ q_{k+1}=F_\theta(q_k), \]

本质上是在逼近时间推进映射。

OpInf 学到的却是：

\[ \boxed{ \dot q=\hat A q+\hat H(q\otimes q)+\hat B u. } \]

因此它显式保留：

  • 状态；
  • 动力学算子；
  • 外部输入；
  • 连续时间结构。

随后仍然可以使用 RK、BDF 等普通积分器求解它。

所以它位于一个很有意思的位置：

\[ \text{Galerkin ROM} \longleftrightarrow \boxed{\text{Operator Inference}} \longleftrightarrow \text{black-box machine learning}. \]

它比 intrusive ROM 少要求求解器内部信息，又比完全黑箱的网络多利用物理结构。这也是当前官方 opinf 文档将其称为适合 glass-box systems 的原因：知道 governing-equation structure，但不能直接查询内部离散算子。

3. 一个很实用的例子：从 Adams/FEM 批量仿真构造动力学代理

假设高保真软件输出机构状态：

\[ x(t)= [ \theta_1,\ldots,\theta_m, \dot\theta_1,\ldots,\dot\theta_m, \text{flexible DOFs} ]^T. \]

先收集多组不同载荷、参数、初值下的轨迹：

\[ X=[x_1,\ldots,x_K]. \]

POD：

\[ X\approx VQ. \]

然后拟合：

\[ \boxed{ \dot q = c+Aq+H(q\otimes q)+Bu. } \]

在线阶段就无需再次调用完整仿真器，而只积分几十维 ODE。

这与普通 Kriging 有一个重要区别：

\[ \text{Kriging:}\quad \mu\rightarrow y \]

通常学习输入到最终响应；

而

\[ \text{OpInf:}\quad (q,u)\rightarrow\dot q \]

学习的是状态演化规律。

因此当你需要：

  • 完整时间历程；
  • 控制；
  • 数字孪生；
  • 参数扫描；
  • 大量 Monte Carlo 动力学仿真；

OpInf 往往比单纯做响应面更自然。

4. 为什么这比 DMD 更进一步？

查看完整推导与细节

Dynamic Mode Decomposition 本质上主要寻找线性动力学：

\[ \dot q=Aq \]

或离散形式

\[ q_{k+1}=Kq_k. \]

而很多物理系统真正需要：

\[ \dot q = Aq+ H(q\otimes q) + G(q^{\otimes3}) +\cdots. \]

OpInf 可以直接利用这种已知的 polynomial structure。

更有意思的是，如果原方程不是多项式，还可以先 lifting。

例如某个非线性：

\[ \dot x=f(x) \]

在原坐标下非常复杂，但引入辅助变量

\[ z=\phi(x) \]

后可能变成 quadratic system：

\[ \dot z=Az+H(z\otimes z). \]

Lift & Learn 正是利用物理知识寻找这种 lifted representation，再用 OpInf 学习低维算子；在 FitzHugh–Nagumo 和可压缩 Euler 等案例中，它展示了这种方法对输入变化的泛化能力。

5. 它真正困难的地方不是最小二乘，而是“可辨识性”

查看完整推导与细节

把所有未知算子拼起来，可以写成

\[ D\,O\approx R. \]

如果训练轨迹太单一，例如永远只从同一个初值、同一种载荷运行，那么数据矩阵 \(D\) 可能严重病态：

\[ \kappa(D)\gg1. \]

此时很多完全不同的 \(\hat A,\hat H\) 都能解释训练数据。

表现就是：

\[ \boxed{\text{训练轨迹拟合极好，离开训练工况立即发散。}} \]

所以 OpInf 的核心工程问题其实变成了：

\[ \boxed{\text{怎样设计足够“激励系统”的训练仿真？}} \]

这和系统辨识中的 persistent excitation 是同一个思想。

对昂贵仿真而言，这甚至会进一步连接主动学习：Active Operator Inference 已经研究了如何在噪声轨迹下主动选择新的 FOM 查询，使推断出的 reduced operators 更可靠。

6. 第二个危险：拟合准确不代表动力学稳定

查看完整推导与细节

最小二乘可能得到

\[ \hat A \]

带有错误的正实部特征值。

于是训练区间内：

\[ q_{\rm ROM}(t)\approx q_{\rm FOM}(t), \]

但长时间积分后：

\[ \|q(t)\|\rightarrow\infty. \]

因此近年的重要方向已经从

\[ \boxed{\text{fit operators}} \]

推进到

\[ \boxed{\text{fit physically admissible operators}}. \]

例如可以约束：

\[ \hat A+\hat A^T\preceq0 \]

来施加耗散结构，或者约束矩阵对称性、正定性、Hamiltonian/gradient structure。相关研究显示，结构约束和 physics-informed regularization 可以在普通或 Tikhonov 拟合产生不稳定 ROM 的情况下得到稳定模型。

这一步非常关键：

\[ \boxed{ \text{ROM 的最终目标不是重放数据， 而是产生正确的动力系统。} } \]

7. 它与前几张 ROM 卡片怎样连接？

现在可以形成一条很清楚的路线：

\[ \text{POD} \]

解决：

\[ \boxed{\text{状态空间太大}} \]

↓

\[ \text{Galerkin ROM} \]

要求：

\[ \boxed{\text{能访问 FOM 内部算子}} \]

若能访问但非线性仍昂贵：

\[ \boxed{\text{DEIM / ECSW / Hyper-reduction}} \]

若不能访问内部算子：

\[ \boxed{\text{Operator Inference}} \]

若原物理结构过于复杂：

\[ \boxed{\text{Lift \& Learn}} \]

再进一步：

\[ \boxed{\text{structure-preserving OpInf}}. \]

所以 OpInf 真正卡在：

\[ \boxed{ \text{传统 projection ROM 与数据驱动 Scientific ML 的接口处。} } \]

今天值得留下的一句话

Operator Inference 最值得学的并不是“用最小二乘拟合一个 ODE”，而是：

\[ \boxed{ \text{当无法获得高保真模型内部算子时， 仍然可以利用已知的物理方程结构， 只从状态轨迹反推出一个 projection-like reduced dynamical system。} } \]

这对工程仿真尤其有迁移价值。很多工业软件对用户而言既不是白盒，也不完全是黑盒——你知道里面在解什么物理问题，也能批量获得高质量轨迹，但拿不到组装后的算子和残差实现。

这正是 OpInf 最适合生存的“灰盒地带”。
