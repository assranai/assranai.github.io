Speculative Decoding：为什么一个“小模型猜答案 + 大模型批量验算”的系统，可以在不改变目标分布的前提下加速大模型

主题：Speculative Decoding / Speculative Sampling（推测解码）
领域：AI 全栈工程 × 大模型推理 × 高性能计算
推荐阅读时间：约 8–10 分钟
上一张卡片讲 Continuous Batching，解决的是：

\[\boxed{\ ext{多个请求之间怎样更高效地共享 GPU}}\]

今天的 Speculative Decoding 解决的是另一个更底层的问题：

\[\boxed{\ ext{单个请求为什么非得一个 token 一个 token 串行生成？}}\]

标准自回归模型：

\[p(x_{1:T}) = \prod_{t=1}^{T} p(x_t\mid x_{导致生成第 \(t+1\) 个 token 前，必须先知道第 \(t\) 个：

\[x_t\rightarrow x_{t+1}\rightarrow x_{t+2}.\]

因此生成 100 个 token，原则上需要约 100 次串行 target-model decoding step。

Speculative Decoding 的关键突破是：

\[\boxed{ \ ext{依赖关系不能消灭， 但可以“猜测未来”，然后并行验证。} }\]

让一个便宜的 draft model 一次猜出：

\[x_{t+1},x_{t+2},\ldots,x_{t+\gamma},\]

再让昂贵的大模型在一次并行 forward中同时检查这些位置。

Leviathan、Kalman、Matias 在 ICML 2023 的工作报告 T5-XXL 上约 \(2\!-\!3\ imes\) 加速；几乎同期 DeepMind 的 Chen 等人在 Chinchilla 70B 上报告约 \(2\!-\!2.5\ imes\) decoding speedup。更关键的是，两套工作的经典 speculative sampling 都能保持 target model 的原始采样分布，而非用质量换速度。

1. 为什么“大模型一次验证 5 个 token”可能和生成 1 个 token 差不多快？

这件事一开始很反直觉。

假设 70B 模型生成一个 token。

GPU 需要把大量：

\[W_Q,W_K,W_V,W_{\rm FFN},\ldots\]

模型权重从 HBM 搬到计算单元。

在低 batch 的 decode 阶段，经常存在：

\[\boxed{\ ext{memory-bandwidth bound}}\]

现象：

算力没有吃满，时间主要花在搬模型权重。

于是：

普通 decode

一次加载这些庞大权重：

\[\rightarrow1\ ext{ 个 token}\]

验证一串候选

还是加载相似的模型权重：

\[\rightarrow \gamma\ ext{ 个 candidate positions 并行评分}\]

后者虽然 FLOPs 更多，却可能没有成比例增加 wall-clock time。

Medusa 对这个瓶颈的表述很直接：自回归 decode 的每一步都需要重新把庞大的模型参数从 HBM 带入计算路径，而计算本身往往没有充分利用 accelerator。

所以 speculative decoding 利用的是：

\[\boxed{\ ext{模型 decode 阶段存在“闲置算力”。}}\]

它拿这些闲置算力来验证未来 token。

设：

\[q\]

是很小的 draft model，

\[p\]

是我们真正想采样的大 target model。

当前上下文：

\[x_{1:t}.\]

Draft 先自回归生成：

\[\ ilde x_{t+1}, \ ilde x_{t+2}, \ldots, \ ilde x_{t+\gamma}.\]

比如：

4
5
6

当前上下文：
"The capital of France"

draft 猜：

[is] [Paris] [,] [which] [is]

这一步很便宜。

接下来 target model 一次性输入：

利用 Transformer 对不同位置并行计算的能力，一次得到：

\[p(x_{t+1}|x_{\le t}),\]\[p(x_{t+2}|x_{\le t+1}),\]

……

\[p(x_{t+\gamma}|x_{\le t+\gamma-1}).\]

于是：

\[\boxed{ \ ext{原本 }\gamma\ ext{ 次昂贵 target decode} }\]

有机会被压缩成：

\[\boxed{\ ext{1 次昂贵 target verification}}\]

。

3. 但这里有一个核心难题：Draft 猜错怎么办？

假设 draft 给：

\[q(\ ext{Paris})=0.50\]

而 target 给：

\[p(\ ext{Paris})=0.80.\]

很好。

但另一个 token：

\[q(\ ext{London})=0.30,\]

target：

\[p(\ ext{London})=0.02.\]

显然不能无条件相信 draft。

最粗暴的办法是：

target 不同意就丢掉。

这对 greedy decoding 可以做得相对简单。

但对于：

\[\boxed{\ ext{sampling}}\]

会产生更深的问题：

你一旦按某种随意规则接受/拒绝 draft token，

最终生成分布就可能不再等于：

\[p.\]

这意味着 temperature、top-p 等采样行为都会被悄悄改变。

经典 speculative sampling 真正漂亮的地方就在这里：

\[\boxed{ \ ext{它把这件事做成了严格的 rejection sampling。} }\]

4. 最值得理解的公式：接受概率

Draft 从：

\[q(x)\]

采样出候选：

\[\ ilde x.\]

Target 对同一个位置给出：

\[p(x).\]

候选的接受概率为：

\[\boxed{ a(\ ilde x) = \min \left( 1, \frac{p(\ ilde x)}{q(\ ilde x)} \right) }\]

。

这条公式非常有意思。

如果 draft：

\[q(\ ilde x)\le p(\ ilde x),\]

那么：

\[\frac pq\ge1,\]

所以：

\[\boxed{a=1}.\]

Draft 对这个 token 没有“过度推荐”，直接接受。

如果：

\[q(\ ilde x)>p(\ ilde x),\]

那么 draft 给这个 token 太多概率。

于是只以：

\[\frac{p}{q}\]

的概率接受。

因此 draft 分布中“超出 target 的部分”会被削掉。

5. 被拒绝以后，不能简单重新从 \(p\) 采样

查看完整推导与细节

这是整个算法最精妙的一步。

假设 candidate 被拒绝。

如果直接重新：

\[x\sim p,\]

实际上会重复计算某些已经通过 acceptance mechanism 获得的概率质量，

最终分布会偏掉。

正确的 correction distribution 是：

\[\boxed{ p'(x) \propto \max(0,p(x)-q(x)) }\]

更严格地：

\[p'(x) = \frac{[p(x)-q(x)]_+} {\sum_y[p(y)-q(y)]_+}.\]

其中：

\[[z]_+=\max(z,0).\]

直觉上：

Draft 已经贡献了一部分：

\[\min(p,q)\]

概率质量。

剩下没有覆盖的恰好是：

\[[p-q]_+.\]

因此：

\[\boxed{ \ ext{接受部分} + \ ext{拒绝后的 correction 部分} = p }\]

。

最终采样分布仍然严格等于 target：

\[\boxed{x\sim p.}\]

这就是“lossless speculative decoding”中 lossless 的真正含义：不是说浮点执行完全逐位一致，而是算法意义上保持 target sampling distribution。

6. 一个离散小例子

查看完整推导与细节

设词表只有：

\[A,B,C.\]

Target：

\[p=(0.6,0.3,0.1)\]

Draft：

\[q=(0.5,0.4,0.1).\]

如果 draft 采到 A：

\[a(A)= \min(1,0.6/0.5)=1.\]

必接收。

如果采到 B：

\[a(B)= \frac{0.3}{0.4}=0.75.\]

如果采到 C：

\[a(C)=1.\]

所以只有 draft 高估 B 的那部分概率质量：

\[0.4-0.3=0.1\]

需要被拒掉。

而：

\[p-q = (0.1,-0.1,0).\]

正部分：

\[[p-q]_+ = (0.1,0,0).\]

因此 B 被拒后，correction 必然选择 A。

最终你可以验证：

\[P(A)=0.6,\quad P(B)=0.3,\quad P(C)=0.1.\]

恰好恢复：

\[p.\]

所以小模型可以“犯错”，只要 target 能正确校正它。

7. 真正决定性能的是 Acceptance Rate

设每轮 draft：

\[\gamma=5\]

个 token。

如果 target 经常接受：

1

✓ ✓ ✓ ✓ ✓

那么一次 target forward 可能推进约 5 个 token。

很好。

如果经常：

1

✓ ✗

那么后面三个 draft token 都失效，因为第二个 token 已经改变了后续上下文。

此时一次 target forward 只推进约 1–2 个 token。

于是 speculative decoding 的关键性能变量并非 draft model 单独的 perplexity，而是：

\[\boxed{\ ext{candidate acceptance rate}}\]

。

粗略设每个 candidate 独立具有接受概率：

\[\alpha.\]

连续接受 token 数的期望约包含：

\[\alpha+\alpha^2+\cdots+\alpha^\gamma.\]

所以：

\[E[N_{\rm accepted}] \approx \frac{\alpha(1-\alpha^\gamma)} {1-\alpha}.\]

如果：

\[\alpha=0.9,\quad\gamma=5,\]

约为：

\[3.69.\]

如果：

\[\alpha=0.5,\]

只约：

\[0.97.\]

因此：

\[\boxed{ \ ext{draft 只需要“便宜”是不够的， 还必须与 target 足够一致。} }\]

8. 这产生了一个很典型的双重 trade-off

Draft 越大：

\[\boxed{\alpha\uparrow}\]

通常预测越准。

但：

\[\boxed{T_{\rm draft}\uparrow}\]

也更贵。

Draft 太小：

\[T_{\rm draft}\downarrow\]

但接受率下降：

\[\alpha\downarrow.\]

所以真正需要优化：

\[\boxed{ \frac{\ ext{每轮有效推进 token 数}} {\ ext{draft cost + verification cost}} }\]

。

存在一个最佳 draft capacity。

这和很多工程问题类似：

\[\boxed{ \ ext{代理模型不是越准越好； 它的精度必须和调用成本一起评价。} }\]

这也是 speculative decoding 对 surrogate modeling 特别有迁移价值的一点。

9. 为什么 Speculative Decoding 本质上也是一种 Multi-Fidelity 方法？

把它换一种语言描述：

低保真模型

\[q(x)\]

便宜、近似。

高保真模型

\[p(x)\]

昂贵、权威。

传统 multi-fidelity 常做：

\[\boxed{ \ ext{低保真筛选} + \ ext{少量高保真校正}. }\]

Speculative decoding 则做：

\[\boxed{ \ ext{低保真提出未来轨迹} + \ ext{高保真并行验证}. }\]

而且非常关键的一点是：

\[\boxed{\ ext{低保真模型永远没有最终决定权。}}\]

因此它和很多 surrogate 加速策略不同：

低保真误差不会直接污染最终输出分布。

这是一种非常强的：

\[\boxed{\ ext{proposal + exact correction}}\]

架构。

10. 这和 MFMC 又有一个重要区别

之前 MFMC 使用低保真模型的方式是：

\[\boxed{ \ ext{利用相关性降低统计估计方差} }\]

。

Speculative decoding 使用低保真模型：

\[\boxed{ \ ext{预测未来高保真计算可能接受的状态} }\]

。

所以两者都利用：

\[\ ext{cheap correlated model},\]

但用途不同：

\[\ ext{MFMC} \rightarrow \ ext{variance reduction}\]\[\boxed{ \ ext{Speculation} \rightarrow \ ext{latency hiding / parallel verification} }\]

。

这是 multi-fidelity 思想一个非常不同的分支。

11. 为什么“Draft 正确率 90%”仍不足以预测 speedup？

查看完整推导与细节

因为 wall-clock 速度还依赖：

\[T_{\rm target}(\gamma)\]

——target 一次验证 \(\gamma\) 个 token 到底比验证 1 个贵多少。

理想情况下：

\[T_{\rm target}(5) \approx T_{\rm target}(1),\]

那么收益巨大。

如果：

\[T_{\rm target}(5) \approx 5T_{\rm target}(1),\]

那完全没有意义。

因此 speculative decoding 的基础条件其实是：

\[\boxed{ \ ext{并行验证多个 token 的边际成本远低于串行生成它们。} }\]

这高度依赖：

  • GPU；
  • batch size；
  • model size；
  • memory bandwidth；
  • attention implementation；
  • draft architecture；
  • serving load。

这也解释了为什么论文中的：

\[2\ imes,3\ imes\]

不能直接理解成任何环境都会得到同样收益。

12. 为什么高并发场景反而可能让它不那么划算？

查看完整推导与细节

这是 speculative decoding 和上一期 Continuous Batching 最重要的联系。

在低并发时，大模型 decode 可能：

\[\boxed{\ ext{memory bound + GPU 算力闲置}}\]

。

Speculative verification 可以利用闲置算力。

但当 Continuous Batching 已经把：

\[B\]

推得很大时，

GPU 本身可能已经非常忙。

这时 speculative verification 增加额外计算：

\[\boxed{\ ext{可能没有“免费算力”可用了。}}\]

于是：

\[\ ext{single-request latency}\downarrow\]

并不自动意味着：

\[\ ext{system throughput}\uparrow.\]

当前 vLLM 文档也把 speculative decoding 的主要目标明确定位在中低 QPS、memory-bound 的 serving workload，而不是所有负载条件。

这点非常重要：

\[\boxed{ \ ext{Speculative Decoding 与 Continuous Batching 既互补，也会争抢同一份 GPU capacity。} }\]

13. 经典双模型方案还有一个现实问题：需要多放一个模型

查看完整推导与细节

假设 target：

\[70B.\]

再部署 draft：

\[7B.\]

这意味着额外：

  • 显存；
  • KV cache；
  • 模型管理；
  • tokenizer compatibility；
  • kernel 调度。

而且：

\[q\]

最好与：

\[p\]

行为高度相关。

这促成了一整条后续研究线：

\[\boxed{ \ ext{能不能不再单独部署一个完整 draft model？} }\]

答案是：可以。

14. Medusa：让大模型自己一次预测多个未来 token

Medusa 不单独放一个完整小模型。

它在模型顶部增加多个轻量 decoding heads。

普通 LM head 预测：

\[x_{t+1}.\]

Medusa heads 进一步尝试预测：

\[x_{t+2}, x_{t+3}, \ldots\]

形成多个候选。

然后用 tree attention 一次验证多条 continuation。

结构可以粗略看成：

1
2
3
4

             → head 1 → t+1
hidden state → head 2 → t+2
             → head 3 → t+3
             → head 4 → t+4

这样避免维护独立 draft LLM。

Medusa 在 ICML 2024 发表；论文报告 Medusa-1 可超过约 \(2.2\ imes\) 加速，进一步联合训练的 Medusa-2 报告约 \(2.3\!-\!3.6\ imes\) 的实验加速范围。

它体现了另一个重要方向：

\[\boxed{ \ ext{未来 token prediction 本身可以成为模型 architecture 的能力。} }\]

15. EAGLE：甚至不一定要在 token 空间里猜

EAGLE 提出了一个更有意思的问题：

Token 很离散、很难预测，那么能不能先预测模型内部 feature？

它观察到高层 hidden feature 的自回归预测可能比直接猜 token 更容易。

于是：

\[h_t \rightarrow \hat h_{t+1} \rightarrow \hat x_{t+1}.\]

EAGLE 使用 lightweight autoregressive head 预测接近顶层的 feature，再由 target model 验证。

其 ICML 2024 工作在 LLaMA2-Chat 70B 上报告约 \(2.7\!-\!3.5\ imes\) latency speedup，并保持最终生成分布。

这揭示了 speculative decoding 的一个更普遍版本：

\[\boxed{ \ ext{“猜未来”不一定发生在输出 token 空间， 也可以发生在内部状态空间。} }\]

16. 到 2026 年，Speculative Decoding 已经从“一个算法”演化成“方法族”

当前 vLLM 文档已经把 speculation 暴露成统一配置，并支持/覆盖多类 proposer 思路，包括：

  • 独立 draft model；
  • n-gram / prompt lookup；
  • suffix-based proposal；
  • MTP（multi-token prediction）；
  • EAGLE 系列等。

当前接口的核心仍然是：

\[\boxed{\ ext{propose several tokens → target verifies}}\]

，只是“谁负责 propose”发生变化。

Hugging Face 当前 Transformers 同样正式支持 assisted/speculative decoding：辅助模型生成候选，主模型一次验证；其文档同时提醒，经典双模型实现的实际收益依赖 assistant 足够小、candidate agreement 足够好等条件。

甚至 2026 年发布的 Gemma 4 Assistant 已专门提供面向 Gemma 4 的 speculative assistant，并通过 KV sharing 复用 target 的 KV cache，从而减少 assistant 自身的 prefill 和 attention 成本。

所以今天再理解 speculative decoding，最好不要把它等同于：

\[\boxed{\ ext{“一个小 LLM + 一个大 LLM”}}\]

而应该理解为：

\[\boxed{ \ ext{cheap proposal mechanism} + \ ext{authoritative parallel verification} }\]

。

17. 它和 Branch Prediction 有什么共同思想？

CPU 遇到：

1
2
3

if (...) {
    ...
}

不知道下一条真正执行哪个分支。

如果等条件确定以后再取指：

\[\boxed{\ ext{流水线会停}}\]

。

所以 CPU：

\[\ ext{predict branch} \rightarrow \ ext{speculatively execute} \rightarrow \ ext{verify}\]

预测对：

\[\ ext{保留工作}.\]

预测错：

\[\ ext{rollback}.\]

Speculative decoding 也是：

\[\boxed{ \ ext{predict future computation} \rightarrow \ ext{execute/verify in parallel} \rightarrow \ ext{accept or discard}. }\]

共同思想是：

\[\boxed{ \ ext{当真正的依赖无法消除时， 可以通过预测跨越依赖。} }\]

这是一种非常普遍的计算机体系结构思想。

18. 对物理求解器，它甚至提供了一个很有野心的类比

假设 nonlinear time stepping：

\[x_{n+1} = \Phi(x_n).\]

传统严格串行：

\[x_n \rightarrow x_{n+1} \rightarrow x_{n+2}.\]

现在有一个非常便宜的 approximate solver：

\[\ ilde\Phi.\]

它先猜：

\[\ ilde x_{n+1}, \ ilde x_{n+2}, \ldots\]

高保真 solver 再检查这些 predicted states。

这和已有的：

\[\boxed{\ ext{Parareal / parallel-in-time}}\]

思想已经相当接近——用 cheap coarse propagator 预测未来，再由 expensive fine propagator 纠正。

所以 speculative decoding 并不是 LLM 特有的魔法。

它属于一个更大的算法母题：

\[\boxed{ \ ext{cheap prediction of serial dependencies} + \ ext{expensive correction} }\]

。

这对物理求解器开发非常值得保留。

19. 对代理模型还有一个更重要的启发：代理不必直接取代高保真模型

通常 surrogate 的目标是：

\[f_H(x) \approx \hat f(x)\]

然后部署时：

\[\boxed{\hat f\ ext{ 替代 }f_H}.\]

于是代理误差直接进入最终答案。

Speculative decoding 展示了另一种用法：

\[\boxed{ \hat f \ ext{ 只负责提出候选， 最终正确性仍由 }f_H\ ext{ 保证。} }\]

于是 surrogate 可以：

  • 很便宜；
  • 不需要极高精度；
  • 允许犯错；

只要：

\[\boxed{\ ext{它经常猜对就有价值。}}\]

这其实是一种非常重要的工程思想。

例如可靠性仿真中，低精度代理可以负责提出：

\[\boxed{\ ext{可能靠近失效面的 candidate samples}}\]

而真正失效标签始终由高保真模型验证。

代理不承担最终真值职责，训练目标就可以发生变化：

从：

\[\min E[(f-\hat f)^2]\]

变成：

\[\boxed{ \max \ ext{proposal usefulness per unit cost}. }\]

这往往是更符合实际系统目标的指标。

20. 一个最值得自己实现的最小实验

查看代码与实现

无需 LLM。

构造一个目标概率分布：

\[p=(0.30,0.25,0.20,0.15,0.10)\]

和 draft：

\[q=(0.28,0.27,0.18,0.17,0.10).\]

实现：

1
2
3
4
5
6
7

candidate ~ q

accept with:
    min(1, p[candidate] / q[candidate])

if rejected:
    sample from normalize(max(p-q, 0))

运行：

\[10^6\]

次。

统计最终频率。

你会发现：

\[\hat p \approx p.\]

然后故意把 rejection correction 改成：

1
2

if rejected:
    sample directly from p

再统计。

结果就会开始偏离：

\[p.\]

这个十几行程序会让你真正理解 speculative sampling 最核心的数学保证。

第二步再模拟：

\[\gamma=1,2,4,8\]

以及不同：

\[\alpha.\]

假设：

\[T_{\rm draft}=0.1, \qquad T_{\rm verify}=1.1\]

估计每生成一个有效 token 的平均成本。

你会很快看到：

\[\boxed{ \gamma\ ext{ 并非越大越好。} }\]

Candidate 太长以后，后部 token 被整体废弃的概率快速增长。

今天值得留下的一句话

Speculative Decoding 最值得记住的不是：

\[a(x)=\min(1,p(x)/q(x)).\]

真正值得记住的是：

\[\boxed{ \ ext{串行依赖不能被删除时， 仍然可以通过“便宜地猜未来 + 昂贵地批量验证” 把一部分串行工作转化成并行工作。} }\]

它在 LLM serving 知识体系中的位置可以理解成：

\[\ ext{Autoregressive decoding}\]\[\downarrow\]\[\boxed{\ ext{Speculative proposal}}\]\[+\]\[\boxed{\ ext{Parallel target verification}}\]\[\downarrow\]\[\ ext{fewer expensive serial target steps}.\]

它与前两张 AI 工程卡恰好组成三个完全不同的优化轴：

\[\boxed{ \ ext{PagedAttention：优化状态内存} }\]\[\boxed{ \ ext{Continuous Batching：优化请求调度} }\]\[\boxed{ \ ext{Speculative Decoding：优化算法关键路径} }\]

真正深的一层则是：

\[\boxed{ \ ext{低保真模型最大的价值，有时并不是替代高保真模型， 而是预测“高保真模型下一步大概率会做什么”。} }\]

一旦低保真预测错误可以被便宜而严格地检测和纠正，你就得到了一种非常强的加速架构：

\[\boxed{ \ ext{approximate speculation} + \ ext{exact authority}. }\]

这个思想完全可以迁移到 AI 之外。
