Hourglass Modes：有限元里最危险的一类“假柔软”

主题：Hourglass modes（沙漏模态 / 零能模态）与 reduced integration stabilization
领域：有限元 × 软体动力学 × 数值方法
推荐阅读时间：约 8 分钟

Hourglass modes 值得学，因为它揭示了一类很容易被误诊的问题：

\[ \boxed{ \text{模型看起来“太软”甚至塌掉， 原因可能并不在材料，而在离散系统根本没有看见某些形变。} } \]

这类问题最典型地出现在低阶、减缩积分（reduced integration）有限元中。Abaqus 官方文档明确指出：减缩积分可能允许某些变形在积分点处不产生应变，从而形成 zero-energy modes；如果这些模式在网格中传播，就会出现 hourglassing。

经典解决框架来自 Flanagan 与 Belytschko 1981 年的工作，他们研究了单点积分一阶四边形/六面体中的零能模态，并提出了正交 hourglass control。

1. 问题从“积分点太少”开始

考虑一个 8 节点线性六面体：

\[ \text{Hex8}. \]

完整积分通常需要：

\[ 2\times2\times2=8 \]

个高斯点。

而 reduced integration 可以只取：

\[ 1 \]

个积分点，通常在元素中心。

这么做非常诱人，因为：

\[ 8\text{ 次应力计算} \rightarrow 1\text{ 次应力计算}. \]

在显式动力学里，这种节约极其可观。

更重要的是，减缩积分还能缓解某些 locking，例如低阶元素的剪切锁死、近不可压缩问题中的过度刚化。Abaqus 也明确把 reduced integration 的优点总结为更低计算成本和对一些锁死问题更好的表现。

但代价在这里：

一个积分点只“观察”元素中心附近的应变。

如果某种节点运动恰好使中心点：

\[ \varepsilon=0, \]

那么材料模型看到的就是：

\[ \sigma=0. \]

即使整个元素肉眼已经发生了严重畸变。

2. 一个最直观的二维例子

看一个四节点方形单元：

1
2
3
4

4 -------- 3
|          |
|          |
1 -------- 2

现在让节点交替移动，例如形成：

1
2
3
4
5
6

4 ←------→ 3
 \        /
  \      /
  /      \
 /        \
1 →------← 2

整个单元已经变成一种“沙漏”形状。

但如果这种节点位移模式设计得刚好使中心积分点的平均应变为零：

\[ B(\xi=0,\eta=0)u=0, \]

那么：

\[ \varepsilon=Bu=0, \]

于是：

\[ \sigma=C\varepsilon=0. \]

内部能：

[ E_{\rm int}

\frac12u^TKu ]

也可能为：

\[ \boxed{0}. \]

于是你得到了一个极其诡异的运动：

\[ \boxed{ \text{节点在变形，但材料不产生恢复力。} } \]

这就是 zero-energy mode。

“Hourglass”这个名字只是因为典型形状看起来像沙漏。

3. 从线性代数看，这件事更清楚

元素刚度：

[ K_e

\int_{\Omega_e} B^TCB,d\Omega. ]

单点积分以后近似：

\[ K_e \approx B_c^T C B_c\,wV. \]

如果存在某个位移：

\[ u_h\ne0 \]

满足：

\[ B_cu_h=0, \]

那么：

\[ K_eu_h=0. \]

因此：

\[ u_h \]

落在刚度矩阵的 null space 里。

当然，有限元本来就应该存在刚体模态：

\[ \text{translation}+\text{rotation}. \]

它们不产生应变是正确的。

问题在于 reduced integration 增加了额外 null modes：

[ \boxed{ \ker K_e

\text{rigid modes} + \text{spurious hourglass modes}. } ]

对三维 8 节点 Hex：

\[ 24 \]

个位移自由度。

单点积分只能直接检测 6 个独立的小应变分量。于是除了 6 个刚体模态外，还会留下 12 个非物理零能自由度，通常可理解为 4 个 hourglass pattern × 3 个空间方向。

这不是“数值误差有点大”。

这是：

\[ \boxed{ \text{离散算子失秩（rank deficiency）} } \]

的问题。

Abaqus 官方文档也直接把 reduced-integration hourglass 描述为使单元 rank-deficient 的 zero-energy modes。

4. 为什么弯曲特别容易激发它？

考虑一根很粗的梁，只在厚度方向用一个 Hex8 reduced-integration 单元。

弯曲时真实应变应当近似：

\[ \varepsilon_{xx}(y)=-\kappa y. \]

中性轴：

\[ y=0 \]

处恰好：

\[ \varepsilon_{xx}=0. \]

如果唯一积分点就在中性轴附近，它看到的可能就是：

\[ \varepsilon\approx0. \]

于是单元几乎不知道自己正在弯曲。

Abaqus 官方给出了同样的典型警告：单层线性减缩积分单元用于弯曲时，所有积分点可能落在中性轴上，因而无法正确抵抗弯曲；其指导建议这类问题厚度方向使用足够多的单元。

所以当你看到：

\[ \text{beam suddenly folds like rubber} \]

第一反应不应总是：

Young’s modulus 太小。

还应该检查：

\[ \boxed{ \text{是不是积分规则根本没有捕捉到这个 deformation mode？} } \]

5. Hourglass control 到底在做什么？

核心思想非常直接。

把节点位移分解成：

[ u

u_{\rm physical} + u_{\rm HG}. ]

其中：

\[ u_{\rm HG} \]

是材料应变积分检测不到的 hourglass component。

然后人为加入：

\[ f_{\rm HG} \]

来阻止这部分运动。

最简单的 stiffness-based 思路近似：

[ \boxed{ f_{\rm HG}

-K_{\rm HG}u_{\rm HG}. } ]

或者用 hourglass generalized coordinate：

[ q_\alpha

\gamma_\alpha^Tu, ]

则：

\[ f_{\rm HG} \sim -\sum_\alpha k_\alpha q_\alpha\gamma_\alpha. \]

这里：

\[ \gamma_\alpha \]

就是 hourglass mode vector。

Flanagan–Belytschko 的经典方法关键就在于构造 hourglass modes，并使它们与物理的 uniform strain modes 和 rigid-body modes 正交，从而尽量只惩罚非物理部分。原论文同时讨论了 elastic 与 viscous 两类控制。

6. 为什么不能直接把 hourglass stiffness 调得巨大？

因为：

\[ K_{\rm HG} \]

是人工刚度。

它不是由真实 constitutive law 自然产生的。

如果：

\[ K_{\rm HG}\rightarrow\infty, \]

虽然 hourglass 消失了，但你同时可能把真实变形也压制掉：

\[ \boxed{ \text{zero-energy problem} \rightarrow \text{artificial over-stiffening}. } \]

Abaqus 官方甚至明确警告，hourglass 参数比默认值大很多可能造成过度刚化，甚至引发不稳定；如果默认控制下 hourglassing 仍然严重，更合理的处理往往是细化网格，而不是继续加大控制系数。

因此 hourglass control 本质上是：

\[ \boxed{ \text{stabilization} } \]

而不是新的物理材料项。

这一区别非常重要。

7. Stiffness control 和 viscous control 有什么区别？

可以把最基本的两类理解为：

Stiffness form

根据 hourglass displacement：

\[ q_{\rm HG} \]

产生恢复力：

\[ f_{\rm HG}\sim-k_{\rm HG}q_{\rm HG}. \]

特点：

  • 静态问题也有效；
  • 会储存人工弹性能；
  • 过强会使结构偏硬。

Viscous form

根据 hourglass velocity：

\[ \dot q_{\rm HG} \]

加入：

\[ f_{\rm HG} \sim -c_{\rm HG}\dot q_{\rm HG}. \]

特点：

  • 动态问题很方便；
  • 直接耗散 hourglass mode；
  • 对准静态低速模态可能效果不同；
  • 引入非物理耗散。

现代工业代码还有混合、assumed-strain、enhanced 等形式。例如 Abaqus Explicit 支持 stiffness、viscous、combined、relax-stiffness 与 enhanced hourglass formulations；LS-DYNA 也提供多种 Flanagan–Belytschko、assumed-strain、Cosserat point 等控制。

8. 这里有一个非常深的关系：Hourglass 和 locking 是一对“相反方向”的离散错误

这是今天最值得理解的地方之一。

Full integration + 低阶插值有时会产生：

\[ \boxed{\text{太多约束}} \]

例如：

\[ \text{shear locking}, \]\[ \text{volumetric locking}. \]

系统表现：

\[ \boxed{\text{假硬}} \]

于是我们减少积分点：

\[ \text{full} \rightarrow \text{reduced}. \]

但积分减得太多，又可能变成：

\[ \boxed{\text{约束不足}} \]

产生：

\[ \text{hourglass modes}. \]

系统表现：

\[ \boxed{\text{假软}} \]

因此一个很好的知识图景是：

\[ \text{over-constrained} \quad \underbrace{\longleftarrow}_{\text{locking}} \quad \text{good discretization} \quad \underbrace{\longrightarrow}_{\text{hourglass}} \quad \text{under-constrained}. \]

所以 reduced integration 并不是“更准确的积分技术”。

它是在做：

\[ \boxed{ \text{解除某些过强离散约束} } \]

代价是可能解除得太多。

Abaqus 对 reduced/full/selective integration 的说明本质上就是围绕这个权衡展开。

9. Selective reduced integration 为什么很聪明？

假设近不可压缩材料：

\[ \nu\rightarrow0.5. \]

体积变化：

\[ J\approx1 \]

受到极强约束。

如果所有应变分量都 full integration，很容易 volumetric locking。

一种更精细的办法是：

\[ \boxed{ \text{体积部分 reduced integration} + \text{偏差部分 full integration}. } \]

这就是 selective reduced integration 的基本思想之一。

它没有把整个 strain space 都降积分阶次，而只对造成 locking 的那部分放松积分。

于是你开始看到更一般的求解器设计原则：

\[ \boxed{ \text{稳定化最好针对“错误模态”， 而不是对整个系统统一加硬或加阻尼。} } \]

这与 hourglass orthogonal control 的思想其实高度一致。

10. 实际计算中怎么知道 hourglass 已经严重了？

最重要的诊断量之一是：

\[ \boxed{E_{\rm HG}} \]

——hourglass control 所做的人工功/能量。

如果：

\[ E_{\rm HG}\approx0, \]

说明稳定化基本没有参与真实动力学。

如果：

\[ E_{\rm HG} \]

已经和真实：

\[ E_{\rm internal} \]

一个量级，则你的仿真结果很可能越来越依赖人工 stabilization。

LS-DYNA 官方建议监测 hourglass energy，并给出一个常用经验准则：

\[ \boxed{ E_{\rm HG} < 10\% \,E_{\rm internal}^{\rm peak} } \]

作为经验性检查，而不是严格数学界限。

这类指标真正有价值的地方是：

它把“求解器偷偷帮了多少忙”量化出来。

11. 这一思想对自研软体求解器特别重要

Hourglass modes 并非只有 Hex8 才值得关注。

更一般地，只要你的离散能量：

\[ E(x) \]

对于某些非刚体方向：

\[ d\ne d_{\rm rigid} \]

满足：

\[ \boxed{ d^T\nabla^2E\,d\approx0, } \]

那么这个方向就是：

\[ \boxed{\text{weakly constrained / zero-energy mode}} \]

候选。

这可能来自：

  • under-integration；
  • 缺少某类 strain energy；
  • constraint graph 拓扑不足；
  • 只保持体积而缺少 shear；
  • bending constraint 不充分；
  • 不合理的 mixed formulation；
  • 某个 constraint gradient 退化。

所以如果一个 tet/soft-body solver 出现：

\[ \text{形状坍缩} \]

但：

\[ E_{\rm elastic} \]

却没有显著升高，一个非常有价值的问题是：

\[ \boxed{ \text{当前能量/约束是否根本看不见这种坍缩模式？} } \]

这比立即增大：

\[ k,\quad \alpha,\quad damping \]

更接近问题本质。

12. 可以给自研求解器做一个很有用的“模态体检”

对于某个静止构型：

\[ x_0, \]

构造局部 stiffness/Hessian：

[ K

\nabla^2E(x_0). ]

求最小几个特征值：

\[ K\phi_i=\lambda_i\phi_i. \]

理论上自由物体应存在：

\[ 6 \]

个刚体零模态：

\[ \lambda_1,\dots,\lambda_6\approx0. \]

然后看：

\[ \lambda_7,\lambda_8,\ldots \]

如果仍然存在大量：

\[ \lambda_i\approx0, \]

就意味着：

\[ \boxed{ \text{你的离散系统可能存在额外未约束模态。} } \]

再把：

\[ \phi_i \]

可视化。

如果出现：

  • 相邻节点交替移动；
  • 棋盘格；
  • 局部折叠；
  • tet 成组剪切却几乎无能量；

那就非常类似 finite-element hourglass diagnosis。

这是一个非常强的 debug 工具。

13. 对 XPBD 也有一个直接迁移

XPBD 中：

\[ C_j(x)=0 \]

的梯度组成一个 constraint Jacobian：

\[ J. \]

如果存在：

\[ d\neq d_{\rm rigid} \]

满足：

\[ Jd\approx0, \]

那么沿这个方向移动：

\[ x\rightarrow x+\epsilon d \]

所有约束一阶上几乎都没有感觉。

这其实就是 XPBD 世界里的 analogue：

\[ \boxed{ \text{constraint-space hourglass mode} } \]

于是：

\[ J^TWJ \]

会出现额外小特征值。

所以如果一个软体拥有很多 constraint，却仍然能以奇怪模式折叠，真正该问的是：

\[ \boxed{ \operatorname{null}(J) \text{ 中除了 rigid modes 之外还有什么？} } \]

这个视角比“把 iteration 从 8 调到 32”强很多。

因为 iteration 再多，也无法解决：

\[ \boxed{ \text{一个根本不存在的约束。} } \]

14. 这和之前讨论的 tet 反转也有一个重要区别

Tet inversion：

\[ J=\det F<0 \]

是几何/材料状态进入不合法区域。

Hourglass：

\[ E\approx0 \]

却发生大形变，是离散算子没有检测到某种形变。

两者可能最终表现得都像：

\[ \text{mesh collapse}, \]

但病因完全不同。

可以粗略分成：

\[ \boxed{ \text{inversion：能量模型/可行域没有阻止非法状态} } \]

与：

\[ \boxed{ \text{hourglass：离散表示没有观测到该状态变化} } \]

一个是：

\[ \text{physics/formulation issue}, \]

另一个更接近：

\[ \text{rank/completeness issue}. \]

这个区分对求解器诊断非常重要。

15. 一个工程上很实用的测试：Zero-Energy Mode Probe

可以给自己的元素单独做如下单元测试。

固定一个元素，其余环境全部关闭：

\[ f_{\rm ext}=0,\qquad \text{contact}=0. \]

然后生成很多随机 nodal perturbations：

\[ u^{(k)}. \]

计算：

[ r_k

\frac{ E(x_0+u^{(k)}) }{ |u^{(k)}|^2 }. ]

再过滤掉刚体位移/旋转。

如果发现某些：

\[ u^{(k)} \]

具有：

\[ \|u^{(k)}\|\gg0 \]

但：

\[ r_k\approx0, \]

就值得直接把这个 mode 可视化。

更系统的版本就是求：

\[ \lambda_{\min}(K) \]

及对应 eigenvectors。

对于自研 element/constraint，这种测试甚至应该和：

  • patch test；
  • rigid-motion invariance；
  • energy-gradient consistency；
  • finite-difference Hessian check

放在同一层级。

今天值得留下的一句话

Hourglass mode 最值得记住的并不是：

“减缩积分单元要加 hourglass control。”

而是一个更普遍的数值思想：

\[ \boxed{ \text{一个物理模型能不能阻止某种错误运动， 首先取决于离散算子能不能“看见”这种运动。} } \]

如果：

\[ Bu=0 \]

或者：

\[ Ju=0, \]

那么你把材料刚度：

\[ E \]

提高一百倍，都未必有意义。

因为：

\[ \boxed{ 100E\times0=0. } \]

所以以后遇到“软体莫名其妙地塌了”，除了检查：

\[ \text{material stiffness}, \quad \text{timestep}, \quad \text{solver iterations}, \quad \text{collision}, \]

还值得多问一个问题：

\[ \boxed{ \text{这个坍缩方向到底有没有进入我的 strain / constraint space？} } \]

这是 hourglass modes 对有限元之外最有迁移价值的一层。
