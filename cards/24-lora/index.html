LoRA：真正高效的“模型适配”，往往不是少改几个参数，而是只允许参数更新发生在低秩子空间里

Sep 06, 2026
阅读时长: 5 分钟

LoRA：真正高效的“模型适配”，往往不是少改几个参数，而是只允许参数更新发生在低秩子空间里

主题：LoRA（Low-Rank Adaptation）与低秩参数更新
领域：AI 全栈工程 × 大模型推理 × 科学机器学习
推荐阅读时间：约 8–10 分钟

LoRA 值得深入理解，因为它表面上是一个“大模型省显存微调技巧”，但更深层的问题其实是：

\[\boxed{ \text{一个拥有数十亿参数的模型，在适配新任务时，真的需要在整个参数空间里自由移动吗？} }\]

LoRA 的回答是：

\[\boxed{ \text{很多任务适配所需的权重变化，本身可能近似低秩。} }\]

于是它不直接优化完整权重更新：

\[\Delta W\in\mathbb R^{d_{\text{out}}\times d_{\text{in}}},\]

而把更新限制成：

\[\boxed{ \Delta W=BA }\]

其中：

\[A\in\mathbb R^{r\times d_{\text{in}}}, \qquad B\in\mathbb R^{d_{\text{out}}\times r},\]

且：

\[r\ll \min(d_{\text{in}},d_{\text{out}}).\]

原始 LoRA 论文正是基于这种 rank decomposition：冻结预训练权重，只训练低秩更新矩阵。作者在 GPT-3 175B 的实验设置中报告，相比完整 Adam 微调，可将可训练参数数量降低约 \(10^4\) 倍、GPU 内存需求降低约 3 倍，同时保持相当或更好的任务性能。

1. 先看完整微调到底浪费在哪里

假设一个 Transformer 线性层：

\[W\in\mathbb R^{4096\times4096}.\]

它拥有：

\[4096^2 \approx 16.8\text{ million}\]

个参数。

完整微调意味着：

\[W \rightarrow W+\Delta W,\]

其中：

\[\Delta W\]

也是一个完整的：

\[4096\times4096\]

矩阵。

即使新任务只是：

让模型适应某种新的写作风格、领域术语或指令格式，

优化器理论上仍然允许：

\[16.8\text{ million}\]

个独立更新方向。

LoRA 质疑的就是这一点：

\[\boxed{ \text{新任务真正需要的自由度，也许远远小于参数矩阵自身维度。} }\]

于是取：

\[r=8.\]

只训练：

\[A\in\mathbb R^{8\times4096},\]\[B\in\mathbb R^{4096\times8}.\]

参数数量变成：

\[2\times4096\times8 = 65536.\]

相比：

\[16.8\text{ million},\]

只有约：

\[0.39\%.\]

这不是简单“少训练一些原参数”。

它实际上重新定义了：

\[\boxed{ \text{允许模型如何变化。} }\]

2. LoRA 真正施加的是一个 rank constraint

完整更新：

\[\Delta W\]

可以是任意矩阵，理论最大秩：

\[\operatorname{rank}(\Delta W) = \min(d_{\rm in},d_{\rm out}).\]

LoRA 写成：

\[\Delta W=BA.\]

于是：

\[\boxed{ \operatorname{rank}(\Delta W)\le r. }\]

这意味着模型更新只能发生在一个低秩结构中。

对输入：

\[x,\]

原层输出：

\[y=Wx.\]

加入 LoRA：

\[y = Wx + BAx.\]

可以按两步理解：

\[x \xrightarrow{A} z\in\mathbb R^r \xrightarrow{B} \Delta y.\]

所以 LoRA 实际做的是：

\[\boxed{ \text{先把高维输入压缩到一个小的 adaptation space， 再从这个空间生成任务相关修正。} }\]

这里的：

\[r\]

就是 adaptation bottleneck dimension。

3. 为什么“低秩”会有效？

这是 LoRA 最值得学的地方。

它不是因为：

参数越少一定越好。

而是基于一个经验观察：

\[\boxed{ \text{大型预训练模型做下游任务适配时， 真正需要改变的功能方向可能具有很低的 intrinsic dimension。} }\]

原始 LoRA 论文专门研究了 adaptation update 的 rank deficiency，并发现即使：

\[r\]

相当小，往往仍能取得接近 full fine-tuning 的性能。

可以把预训练模型理解成已经拥有一个非常丰富的能力空间：

\[\boxed{ \text{语言、知识、推理模式、语法、表征} }\]

下游微调很多时候并不是：

\[\text{重新学习这些能力},\]

而更像：

\[\boxed{ \text{重新组合、偏置或激活已有能力。} }\]

因此更新空间可能天然比原始参数空间低维得多。

4. 一个二维类比

假设系统参数有：

\[1000\]

维：

\[\theta\in\mathbb R^{1000}.\]

但任务变化真正只需要沿两个方向：

\[v_1,\quad v_2.\]

那么：

\[\Delta\theta = a_1v_1+a_2v_2.\]

虽然：

\[\theta\]

是 1000 维，

真正适配自由度却只有：

\[2.\]

LoRA 做的事情，本质上就是寻找一个类似：

\[\boxed{ \text{task adaptation subspace} }\]

的结构。

这和之前讲过的 Active Subspaces 有一个非常有趣的对应：

  • Active Subspace：寻找输入空间里的低维敏感方向；
  • LoRA：假设参数更新空间本身具有低维结构。

二者都建立在同一个更一般的思想上：

\[\boxed{ \text{名义维度很高，不代表有效自由度真的很高。} }\]

5. 为什么 LoRA 比“冻结大部分层”更加精细？

另一种参数高效方法是：

1
2

冻结前 30 层
只训练最后 2 层

这等于假设：

\[\boxed{ \text{任务变化只发生在某些特定层。} }\]

LoRA 的假设不同：

\[\boxed{ \text{许多层都可以变化， 但每一层只需要少量低秩变化方向。} }\]

这通常更灵活。

例如一个 attention projection：

\[W_q\]

可能只需要轻微改变若干 feature directions。

另一个：

\[W_v\]

也需要适配。

LoRA 可以分别给它们：

\[\Delta W_q=B_qA_q,\]\[\Delta W_v=B_vA_v.\]

于是变化是：

\[\boxed{ \text{distributed but low-dimensional} }\]

，而不是：

\[\text{localized but full-dimensional}.\]

这是两种完全不同的 inductive bias。

6. 为什么它能显著省显存？

训练模型时，显存不只是存：

\[W.\]

还要存：

  • gradient；
  • optimizer states；
  • activation；
  • temporary buffers。

以 Adam 为例，每个 trainable parameter 通常还会有：

\[m,\quad v\]

两个 optimizer states。

如果完整微调：

\[10^9\]

参数，就意味着这些状态也全部存在。

LoRA 冻结：

\[W_0.\]

只优化：

\[A,B.\]

于是：

\[\boxed{ \text{optimizer state 和 gradient memory 只跟 LoRA 参数数量增长。} }\]

这也是为什么 PEFT 在消费级 GPU 上非常有价值。Hugging Face 当前 PEFT 官方文档仍把 LoRA 作为最主要的参数高效微调方法之一，并强调只更新少量 adapter 参数可显著降低训练和存储成本。

7. LoRA 的 inference 为什么可以几乎没有额外结构成本？

因为：

\[W_{\rm adapted} = W_0+BA.\]

训练结束以后，可以直接做：

\[\boxed{ W' = W_0+BA }\]

把 LoRA merge 回原权重。

于是 inference 仍然只是：

\[y=W'x.\]

不需要额外 adapter branch。

这也是原始 LoRA 相比某些传统 adapter architecture 的重要工程优势之一：原论文强调 LoRA 可以避免额外 inference latency。

但现代 serving 中也经常不 merge。

为什么？

因为同一个 base model 可以挂：

1
2
3
4
5
6

Base LLM
 ├─ Finance LoRA
 ├─ Coding LoRA
 ├─ Legal LoRA
 ├─ Game NPC LoRA
 └─ Internal Tool LoRA

于是：

\[\boxed{ \text{一个大模型权重} + \text{很多轻量任务增量} }\]

就能支持多租户、多角色、多领域部署。

这是 LoRA 的系统价值，不只是训练价值。

8. 这和版本控制有一个很好的类比

假设 base model：

\[W_0\]

有：

\[20\text{ GB}.\]

有 100 个不同客户。

Full fine-tuning 要保存：

\[100\times20 = 2000\text{ GB}.\]

LoRA 则保存：

\[W_0\]

一次，然后每个客户只保存：

\[\Delta W_i=B_iA_i.\]

如果每个 LoRA：

\[100\text{ MB},\]

总量大约：

\[20+100\times0.1 = 30\text{ GB}.\]

这实际上是一种：

\[\boxed{ \text{base state + delta state} }\]

架构。

它和：

  • Git delta；
  • patch；
  • copy-on-write；
  • layered filesystem；

的系统思想很相似。

所以 LoRA 在部署层面的本质，也可以理解为：

\[\boxed{ \text{不要复制整个系统状态，只保存任务相关差分。} }\]

9. Rank \(r\) 到底控制什么？

LoRA 最重要的超参数之一：

\[r.\]

如果：

\[r=1,\]

那么：

\[\Delta W=ba^T\]

只能产生一个 rank-1 更新。

表达能力非常有限。

随着：

\[r\uparrow,\]

允许的 adaptation subspace 越丰富。

但同时：

\[\boxed{ \text{参数量、计算量、显存} }\]

都增加。

于是：

\[r\]

本质上是：

\[\boxed{ \text{adaptation capacity budget} }\]

。

一个很重要的工程认识是：

所有层不一定需要相同 rank。

有些层：

\[r=4\]

就够。

有些层可能需要：

\[r=32.\]

这也自然引出了 AdaLoRA、rank allocation 等后续方法。

10. LoRA 并不是简单地“做 SVD”

这一点很容易误解。

LoRA 并不是：

  1. 先完整 fine-tune；
  2. 得到 \(\Delta W\)；
  3. 再做 SVD；
  4. 保留前 \(r\) 个奇异值。

真正训练时：

\[A,B\]

从一开始就是优化变量。

也就是说模型直接搜索：

\[\boxed{ \operatorname{rank}(\Delta W)\le r }\]

这个低秩参数空间。

所以 LoRA 是：

\[\boxed{ \text{low-rank parameterization} }\]

而不是：

\[\text{post-hoc matrix compression}.\]

区别非常重要。

前者改变优化问题本身。

11. 为什么 \(A,B\) 的训练动力学也很重要？

查看完整推导与细节

把：

\[\Delta W=BA\]

分解以后，参数化不再唯一。

例如：

\[BA = (BS)(S^{-1}A)\]

对可逆：

\[S\]

都成立。

所以：

\[A,B\]

之间有 scaling freedom。

这意味着优化器看到的参数空间 geometry 和直接优化：

\[\Delta W\]

并不一样。

2024 年 LoRA+ 就专门指出，随着模型 width 增大，给：

\[A,B\]

使用相同 learning rate 会导致低效 feature learning；其方法为两组矩阵使用不同学习率，在论文实验中报告最高约 \(2\times\) 微调速度提升以及约 1–2% 的性能改进。

这个结果很有启发性：

\[\boxed{ \text{选择低维参数化以后， 优化几何本身也随之改变。} }\]

所以“降维”不是免费的。

12. LoRA-FA 又揭示了另一个系统问题：参数少，不等于 activation 少

查看完整推导与细节

普通 LoRA 虽然 trainable parameters 大幅减少，

但为了计算：

\[A x\]

和：

\[B(Ax),\]

训练时仍需要保存相应 activation。

所以显存瓶颈并没有完全消失。

LoRA-FA 的做法是固定其中一个投影矩阵，只更新另一部分，从而减少需要保存的 activation；论文报告相比标准 LoRA 可进一步降低总体训练内存，最高约 \(1.4\times\)。

这提醒我们：

\[\boxed{ \text{参数压缩} \neq \text{训练系统整体压缩} }\]

工程优化必须同时看：

  • parameters；
  • gradients；
  • optimizer states；
  • activations；
  • communication。

这一点和物理求解器非常类似：DOF 少了，并不代表 sparse solve 就一定便宜。

13. LoRA 真正有迁移价值的部分：低秩“更新”，不是低秩“模型”

这一点尤其值得区分。

LoRA 并没有假设：

\[W_0\]

本身低秩。

事实上预训练权重可以是：

\[\boxed{\text{full-rank}}\]

。

它只假设：

\[\boxed{ \Delta W }\]

近似低秩。

这是一种非常强的建模思想：

\[\boxed{ \text{复杂系统本身可以是高维的， 但从一个已知良好状态到另一个邻近状态的变化可能是低维的。} }\]

这个思想远远不只属于 LLM。

14. 这和有限元中的低秩更新高度相似

设结构刚度矩阵：

\[K_0.\]

只有局部参数变化：

  • 一个连接点刚度变化；
  • 少数单元材料改变；
  • 边界条件小范围改变。

于是：

\[K = K_0+\Delta K.\]

很多时候：

\[\Delta K\]

虽然嵌在巨大：

\[N\times N\]

系统里，但本身影响的自由度很少。

于是可以写成近似：

\[\boxed{ \Delta K = UV^T. }\]

那么：

\[(K_0+UV^T)^{-1}\]

就可能利用 Woodbury identity：

\[(A+UCV)^{-1} = A^{-1} - A^{-1}U (C^{-1}+VA^{-1}U)^{-1} VA^{-1}.\]

也就是说：

\[\boxed{ \text{无需把整个系统重新当成一个全新问题。} }\]

LoRA 和这种思维非常接近：

\[\boxed{ \text{base operator} + \text{low-rank correction}. }\]

15. 这对代理模型也有一个非常好的启发

假设已经有一个基础代理：

\[f_0(x)\]

对应工况 A。

现在工况 B：

  • 材料稍有变化；
  • 边界条件变化；
  • 软件模型升级；
  • fidelity 提升。

最粗暴做法：

\[\boxed{ \text{重新训练一个完整 surrogate} }\]

。

但如果新旧任务差异：

\[\delta f(x) = f_B(x)-f_A(x)\]

具有低维结构，

更合理的做法可能是：

\[\boxed{ f_B = f_0 + \Delta f_{\rm low-dimensional}. }\]

这和 multifidelity discrepancy modeling 很接近。

LoRA 提醒我们：

\[\boxed{ \text{迁移学习真正应该建模的， 往往是任务之间的“变化”， 而不是重新建模整个任务。} }\]

这是代理模型中非常值得吸收的一层。

16. 对可靠性模型同样成立

假设已有一个极限状态代理：

\[g_0(x)\]

对应 nominal design。

设计稍微变化：

\[d_0\rightarrow d_1.\]

通常会重新生成：

\[N\]

个高保真样本，重训：

\[g_1(x).\]

但如果：

\[g(x,d)\]

对设计变化主要发生在某个低维 response direction 上，

则可能构造：

\[\boxed{ g_1(x) = g_0(x) + \Delta g(x) }\]

并只学习：

\[\Delta g.\]

这其实就是一种：

\[\boxed{ \text{surrogate adaptation} }\]

。

LoRA 最大的研究启发之一，就是让人去问：

多工况、多设计、多 fidelity 的代理模型之间，真正需要独立学习的自由度到底有多少？

17. 对游戏引擎 / Agent 部署，一个特别现实的价值：共享 base，动态挂 adapter

假设一个游戏中需要：

  • 商人 NPC；
  • 战斗教官；
  • 世界观讲解者；
  • 任务生成器；
  • QA 助手。

每个角色都完整部署一个：

\[8B\]

模型通常不现实。

LoRA 架构允许：

\[\boxed{ \text{同一个 base model} + \text{多个轻量 adapter}. }\]

服务端可以根据请求动态选择：

\[A_i,B_i.\]

这和前一期 PagedAttention 所体现的思路非常相似：

  • PagedAttention：共享/虚拟化 KV memory；
  • LoRA：共享 base parameters，只保存任务增量。

两者都是：

\[\boxed{ \text{把“大而稳定的公共部分” 与 “小而动态的差异部分” 分离。}\]

这是现代 AI serving 很核心的一种架构思想。

Hugging Face 当前 PEFT 已支持加载、切换、删除不同 LoRA adapters，并支持 tensor parallel 等部署场景。

18. LoRA 的局限：低秩假设不是永远成立

如果新任务与 base model 相距很远：

\[\boxed{ \text{domain shift 很大} }\]

或者需要：

  • 大规模新知识；
  • 新语言；
  • 新视觉模式；
  • 全新推理结构；

那么：

\[r\]

可能必须不断增加。

最终：

\[r\rightarrow d.\]

LoRA 的优势就会逐渐消失。

因此：

\[\boxed{ \text{LoRA 最适合“已有模型附近的任务适配”， 而不是所有形式的知识重建。} }\]

它依赖一个隐含条件：

\[\boxed{ \text{base representation 已经足够好。} }\]

19. 另一个局限：低秩不等于低函数复杂度

即使：

\[\Delta W\]

只有 rank 4，

经过：

\[100\]

层网络、非线性、attention 后，

最终函数变化：

\[\Delta f(x)\]

仍然可能非常复杂。

所以不要简单理解为：

\[r=8 \Rightarrow \text{模型只学 8 个功能}.\]

\(r\) 控制的是：

\[\boxed{ \text{单个权重更新矩阵的线性代数自由度} }\]

而不是最终模型行为的直接语义维数。

这是理解 LoRA 时一个非常重要的边界。

20. 一个很值得自己做的最小实验

查看完整推导与细节

即使不训练 LLM，也可以用一个小 MLP 理解 LoRA。

先训练：

\[f_0(x)\]

拟合：

\[y=\sin x.\]

然后新任务：

\[y=\sin x+0.2\sin3x.\]

固定原模型。

只对其中一个：

\[W\in\mathbb R^{128\times128}\]

加入：

\[\Delta W=BA.\]

分别尝试：

\[r=1,2,4,8,16.\]

比较：

\[\boxed{ \text{validation error} }\]

与：

\[\boxed{ \text{trainable parameter count}. }\]

然后再和 full fine-tuning 比较。

最值得看的问题是：

\[\boxed{ \text{性能在什么 rank 后开始饱和？} }\]

如果：

\[r=4\]

已经和：

\[r=64\]

几乎一样，

你就实际看到了：

\[\boxed{ \text{task adaptation 的 intrinsic rank 很低。} }\]

今天值得留下的一句话

LoRA 最值得记住的并不是：

\[\Delta W=BA.\]

真正值得记住的是：

\[\boxed{ \text{一个系统可以极其高维， 但“从一个已经很好状态到另一个任务状态的变化” 可能只占据很小的低维子空间。} }\]

所以它在整个知识体系中的位置更应该理解成：

\[\text{Large pretrained model}\]\[\downarrow\]\[\boxed{\text{Low-rank update subspace}}\]\[\downarrow\]\[\text{Parameter-efficient adaptation}.\]

而这个思想可以迁移到很多地方：

\[\boxed{ \text{base model} + \text{low-dimensional correction} }\]

可能对应：

  • LLM：LoRA；
  • FEM：low-rank stiffness update；
  • 代理模型：discrepancy adaptation；
  • 多保真模型：低维 fidelity correction；
  • 游戏/Agent 部署：base model + task adapters；
  • 优化：在低维更新空间内搜索。

它真正教会我们的，是一个非常普遍的工程原则：

\[\boxed{ \text{面对一个已经很复杂、但已经工作良好的系统， 优先学习“怎样改变它”， 而不一定重新学习“整个系统是什么”。} }\]

  3. Hugging Face PEFT — LoRA 官方文档。目前最实用的工程入口，包含 LoraConfig、target modules、rank、LoRA-FA、LoRA+、adapter 加载/切换以及 tensor parallel 支持。
    PEFT LoRA 文档

  4. Hayou, Ghosh & Yu, LoRA+: Efficient Low Rank Adaptation of Large Models, 2024。适合进一步理解：选了低秩参数化以后，\(A/B\) 两个因子的优化尺度为什么本身会成为问题。

  5. Zhang et al., LoRA-FA: Memory-efficient Low-rank Adaptation for Large Language Models Fine-tuning, 2023。适合从“参数效率”继续走到“完整训练系统效率”，尤其是 activation memory 为什么仍可能成为瓶颈。
