IPC：把“碰撞处理”改写成一个优化问题

主题：Incremental Potential Contact（IPC，增量势接触）
领域：有限元 × 物理引擎 × 接触力学 × 非线性动力学
推荐阅读时间：约 8 分钟

今天选 IPC，是因为它背后有一个很值得迁移的思想：当碰撞、材料变形和时间积分彼此打架时，与其不断增加碰撞修正、投影、clamp 和事后补丁，可以尝试把它们统一写进同一个变分问题。

IPC 由 Minchen Li 等人在 SIGGRAPH 2020 系统提出，用于大变形非线性弹性动力学中的接触问题。论文报告了最高约 230 万四面体、单步约 49.8 万接触的测试，并强调在极端压缩和大变形下保持无相交、无反转的可行轨迹。

这与你近期接触的软体求解器问题尤其相关，因为 IPC 给出了一条和 PBD/XPBD 很不同的路线。

1. IPC 在整个知识体系里的位置

先看传统软体模拟的一条典型流水线：

\[ \text{弹性内力} \rightarrow \text{时间积分} \rightarrow \text{碰撞检测} \rightarrow \text{穿透修正} \rightarrow \text{速度修正} \]

这里存在一个结构性问题。

弹性求解器可能得到一个它认为合理的位置 \(x\)，碰撞模块随后说：

这个位置非法，改掉。

于是碰撞模块把位置投影到另一个位置 \(x'\)。

但 \(x'\) 并不一定满足原来的弹性能量最小化问题。

下一步弹性约束又试图恢复材料形状，碰撞约束再次阻止它，于是容易出现：

  • 接触抖动；
  • 大量 constraint fighting；
  • 四面体压扁；
  • 接触附近异常刚化；
  • 能量注入；
  • 极端情况下元素反转。

IPC 的关键改变是：

接触本身也是能量。

于是系统从“动力学求解 + 碰撞修正”变成一个统一优化问题。

这就是 IPC 在体系中的真正位置：

\[ \boxed{ \text{Time integration} + \text{FEM energy} + \text{Contact} + \text{Friction} \rightarrow \text{Incremental potential minimization} } \]

它属于 variational / optimization-based dynamics 这条路线，而不只是某个更好的 collision response 算法。原论文明确将其定位为 nonlinear elastodynamics 的 robust and accurate time stepping 方法。

2. 第一步：把隐式时间积分写成最小化

考虑

\[ M\ddot x=-\nabla E(x)+f_{\rm ext}. \]

这里：

  • \(M\)：质量矩阵；
  • \(E(x)\)：弹性势能；
  • \(x\)：节点位置。

例如 Neo-Hookean FEM 中：

\[ E(x)=\sum_e V_e^0\Psi(F_e(x)). \]

对于 Backward Euler，可以把下一时刻的位置写成类似下面的优化问题：

[ x^{n+1}

\arg\min_x \left[ \frac{1}{2h^2} |x-\tilde{x}|_M^2 + E(x) \right]. ]

其中

[ \tilde{x}

x^n+h v^n+h^2M^{-1}f_{\rm ext} ]

可以理解为如果不存在弹性约束，节点惯性希望去的位置。

因此目标函数有两个竞争项：

\[ \underbrace{ \frac{1}{2h^2}\|x-\tilde{x}\|_M^2 }_{\text{惯性}} + \underbrace{ E(x) }_{\text{材料}} \]

系统最终选择二者折中的最低能量位置。

这个思想本身并不是 IPC 发明的；IPC 的精彩之处发生在下一步。

3. 把“不允许穿透”也变成势能

假设两个几何 primitive 的距离为

\[ d(x). \]

传统方法可能规定

\[ d(x)\ge 0 \]

然后在违反约束后投影。

IPC 引入 barrier potential：

\[ B(d)= \begin{cases} -\kappa(d-\hat d)^2 \ln\left(\frac d{\hat d}\right), & 0其中：

  • \(\hat d\)：barrier 开始作用的距离；
  • \(\kappa\)：barrier stiffness。

最重要的是：

\[ \boxed{ \lim_{d\rightarrow0^+}B(d)=+\infty } \]

也就是说：

两个表面越接近真正的碰撞状态，继续靠近所需要支付的能量代价越大。

于是新的时间步成为

[ x^{n+1}

\arg\min_x \left[ \frac{1}{2h^2} |x-\tilde{x}|M^2 + E{\rm elastic}(x) + B_{\rm contact}(x) \right]. ]

这一步非常重要。

碰撞和材料现在处于同一个优化问题中。

不存在“FEM 算完以后 collision solver 再把结果改掉”这一层逻辑分裂。

4. 为什么 barrier 比 penalty 更深一层？

Penalty contact 常见形式：

\[ E_p(d)=\frac12 k\min(d,0)^2. \]

它的逻辑是：

\[ d<0 \]

已经发生穿透以后，再产生恢复力。

所以 penalty 方法本质允许：

\[ \boxed{\text{先违法，再惩罚}} \]

而 barrier 的定义域直接限制在：

\[ d>0. \]

并且：

\[ B(d)\rightarrow\infty \quad(d\rightarrow0^+) \]

因此其数学结构变成：

\[ \boxed{\text{永远不要进入非法区域}} \]

这与 interior-point optimization 中 barrier method 的思想高度一致。

这也是 IPC 名字里 Potential Contact 的真正含义。

5. 但仅有 barrier 仍然不够

这里出现一个很漂亮的数值问题。

假设 Newton 迭代得到：

\[ x_{k+1}=x_k+\alpha p. \]

即使：

\[ x_k \]

完全无穿透，也不能保证

\[ x_k+p \]

没有穿透。

例如两个三角形可能在 Newton step 中直接穿过去。

所以 IPC 又引入 Continuous Collision Detection（CCD）。

CCD 求的是：

[ \alpha_{\rm collision}

\min{ \alpha: d(x_k+\alpha p)=0 }. ]

然后 line search 强制：

\[ \alpha < \alpha_{\rm collision}. \]

于是 Newton optimization 的路径本身也保持 collision-free。

这形成了 IPC 最重要的组合：

\[ \boxed{ \text{Barrier Energy} + \text{CCD} + \text{Line Search} } \]

barrier 负责：

终点不能碰撞。

CCD 负责：

走向终点的路径也不能穿过去。

IPC 因而能够构造 intersection-free trajectories，而不仅仅是让离散帧最终看起来没有穿透。

6. 一个直观例子：把软体挤进细管

设一个 Neo-Hookean 四面体软体被刚体活塞压进比自身窄很多的管道。

传统求解器可能经历：

\[ \text{compression} \rightarrow \text{penetration} \rightarrow \text{projection} \rightarrow \text{tet distortion} \rightarrow J\downarrow \rightarrow \text{inversion}. \]

IPC 则同时考虑：

\[ E_{\rm inertia} + E_{\rm NH} + E_{\rm contact}. \]

Newton optimizer 会寻找：

在保持材料响应的同时，又不进入 collision barrier 的最低增量势状态。

IPC 项目主页展示的代表性 stress test 就包括：一个板将大量复杂 Neo-Hookean 四面体模型压入狭窄障碍物中，并保持无相交、无反转。

所以 IPC 的强项尤其集中在：

\[ \boxed{ \text{large deformation} + \text{dense contact} + \text{high stiffness} } \]

这恰恰是很多实时软体方法最容易崩掉的区域。

7. 一个值得记住的思想：feasibility 和 accuracy 分离

IPC 有一个很有工程价值的设计哲学：

数值精度可以降低，但几何可行性尽量不能降低。

论文专门测试了较宽松求解容差；在动画等低精度需求下，即使降低优化精度，也仍可以维持 feasibility 和 plausible behavior。

这实际上给物理引擎设计提供了一种很有价值的层次：

\[ \text{Hard invariant} \]

例如：

\[ d>0,\qquad J>0 \]

与

\[ \text{Soft accuracy target} \]

例如：

\[ \|\nabla E\|<\epsilon \]

应该分开。

实时引擎完全可以允许：

\[ \epsilon=10^{-3} \]

而不是：

\[ 10^{-8}, \]

但最好不要允许：

\[ J<0. \]

这是比“所有东西都调 tolerance”更清晰的求解器设计原则。

8. IPC 与 XPBD 的根本区别

XPBD 更接近：

\[ C_i(x)=0 \]

然后依次更新：

\[ x\leftarrow x+\Delta x_i. \]

也就是 constraint projection / iterative constraint solving。

它的优势非常明显：

  • 算法简单；
  • 易实时化；
  • 易并行；
  • iteration budget 可控；
  • 非常适合游戏。

IPC 更接近：

[ x^*

\arg\min E_{\rm total}(x). ]

然后使用 Newton 类优化：

\[ H\Delta x=-g. \]

所以 IPC 的代价也很明显：

  • Hessian 构造复杂；
  • broad phase + CCD 成本高；
  • sparse linear solve 很重；
  • barrier conditioning 会变差；
  • 相比 XPBD 更难满足严格实时预算。

因此 IPC 未必是“下一代游戏 XPBD”。

它更像一个高鲁棒性的参照系：

如果一个接触问题理论上应该怎么处理，IPC 给出了非常干净的答案；实时物理引擎则可以研究如何近似这个答案。

这也是为什么它特别值得物理引擎开发者读。

9. 一个更值得继续追的方向：IPC 本身也在演化

IPC 并没有停在 2020 年。

2021 年的 **Codimensional IPC（C-IPC）**进一步统一了：

  • volumetric solids；
  • shells / cloth；
  • rods / hair；
  • particles；

并加入 thickness 与 strain limiting 等处理，使 codimension 0/1/2/3 的结构可以在统一框架中进行摩擦接触。

更值得注意的是，IPC Toolkit 到 2026 年 2 月发布的 v1.5.0 又加入了：

  • Geometric Contact Potential；
  • Offset Geometric Contact；
  • fully parallel LBVH broad phase；
  • collision normal / signed distance / dihedral angle 的 gradient 与 Hessian utilities。

所以 IPC 已经逐渐从“一篇 SIGGRAPH 算法”发展成一个接触动力学方法族与工程工具链。

10. 对你当前求解器研究最值得迁移的一点

如果一个软体系统出现：

\[ J\downarrow \rightarrow \text{barrier activates} \rightarrow \text{仍继续坍缩} \]

很容易继续沿着：

\[ \kappa\uparrow,\qquad compliance\downarrow,\qquad iterations\uparrow \]

这条路调参数。

IPC 提供了另一个诊断角度：

检查不同物理约束是否真的属于同一个一致的离散系统。

尤其值得检查：

\[ \text{elasticity} \leftrightarrow \text{contact} \leftrightarrow \text{volume/inversion prevention} \leftrightarrow \text{velocity update}. \]

如果四者分别通过不同投影、不同 λ 历史、不同速度修正机制作用，那么即使每个模块单独正确，组合后仍可能产生不一致。

因此可以把 IPC 当作一个“理论上限”：

\[ \boxed{ \text{统一能量} \rightarrow \text{统一优化} \rightarrow \text{可行域保护} } \]

然后再问一个很有研究价值的问题：

能不能保留 IPC 的 invariant / feasibility 思想，同时获得 XPBD 的实时计算结构？

这条问题链会自然连接到 barrier-augmented XPBD、variational PBD、projective dynamics、ADMM、nonlinear Gauss-Seidel，以及 GPU-friendly contact optimization。

这比单纯继续增加一个防反转 constraint，研究空间要大得多。

今天值得留下的一句话

\[ \boxed{ \text{Robustness often comes from changing the formulation, not tuning the solver.} } \]

当一个物理求解器开始依赖越来越多的 clamp、阈值、特殊分支和事后修正时，值得检查的可能已经不只是参数，而是问题有没有被放在正确的数学形式里。

想看真正的工程结构，可以直接读 IPC Reference Implementation。官方仓库同时给出了 Neo-Hookean、Fixed Corotational、Backward Euler/Newmark、CCD、稀疏线性求解等实际实现入口。

进一步研究薄壳、布料、杆和毛发，推荐 Codimensional IPC，对应 SIGGRAPH 2021。

如果准备自己实现，可以进一步看现在仍在维护的 IPC Toolkit；2026 年版本已经包含更新的 contact potential、并行 broad phase 以及大量导数工具。

最后，Danny M. Kaufman 的 个人主页与论文列表 很适合沿着 IPC → C-IPC → intersection-free rigid body dynamics → injective deformation 这条研究脉络继续往下挖。

延伸讨论

问： 提问：看起来ccd才是起到碰撞合法决定性作用的约束

对。如果只问“是什么机制从几何上保证这一 Newton 步不会穿透”，CCD 确实是决定性的。 不过 IPC 的关键在于：CCD 和 barrier 分别解决了两个不同层次的问题。

可以把它们拆开：

\[ \boxed{\text{CCD：保证搜索路径合法}} \qquad \boxed{\text{Barrier：决定合法区域内的物理解}} \]

1. CCD 真正保证的是什么？

假设当前状态 \(x_k\) 合法，Newton 给出方向 \(p\)：

\[ x(\alpha)=x_k+\alpha p. \]

如果直接取 \(\alpha=1\)，两个三角形可能从彼此两侧直接穿过去。

CCD 求第一次发生接触的时刻：

\[ \alpha_c=\min\{\alpha\in(0,1]\mid d(x_k+\alpha p)=0\}. \]

然后限制：

\[ \alpha < \alpha_c. \]

所以只要初始状态满足

\[ d(x_k)>0, \]

CCD + line search 就可以维持

\[ d(x_{k+1})>0. \]

从这个意义上，你的判断完全成立：

IPC 的“intersection-free”几何可行性，直接执行者确实是 CCD。

2. 那 barrier 为什么仍然不可替代？

考虑一个极端情况：只有 CCD，没有 barrier。

Newton 给出的 unconstrained solution 想让两个物体穿过去：

1
2
3

当前状态                  unconstrained目标
 A       B                   B       A
 |       |        →          |       |

CCD 发现要撞了，于是每次都截断：

\[ \alpha\le\alpha_c. \]

问题来了：截断以后往哪里走？

CCD 只会告诉优化器：

“你这一步最多走到这里。”

它不会告诉优化器：

“发生接触以后，应该沿什么方向运动、产生多大的接触反力、怎样与弹性力达到平衡。”

因此 CCD 更像一个可行域守门员，而不是接触力模型。

Barrier 则提供

\[ f_c=-\nabla B(d), \]

以及 Newton 求解需要的

\[ H_c=\nabla^2B(d). \]

随着

\[ d\rightarrow0^+, \]

接触势能迅速增加，于是优化问题本身开始“知道”不能继续朝这个方向走。

因此 Newton direction 会发生改变：

[ p

-H^{-1}g ]

其中现在

[ g

g_{\rm inertia} + g_{\rm elastic} + \underbrace{g_{\rm contact}}_{\nabla B}. ]

也就是说，barrier 改变的是搜索方向；CCD 限制的是沿这个方向最多能走多远。

这一区别非常关键。

3. 用一个简单例子就能看出来

一个弹性球高速撞墙。

只有 CCD：

\[ \text{球飞向墙} \rightarrow \text{CCD发现碰撞} \rightarrow \text{截断步长} \rightarrow ??? \]

它知道“不能穿墙”，但没有完整定义接触后的动力学响应。

Barrier + CCD：

\[ \text{球飞向墙} \rightarrow B(d)\uparrow \rightarrow \nabla B\text{产生接触作用} \rightarrow \text{Newton方向改变} \]

同时 CCD 保证 Newton 迭代过程中不会因为步子太大而：

\[ d>0\rightarrow d<0. \]

所以两者实际上形成了一个非常漂亮的分工：

机制 回答的问题
Barrier 下一步应该往哪里走？
CCD 沿这个方向最多能走多远？

4. 更深一层：这和你做的 \(J\)-barrier 很像

这里其实能直接联系到四面体反转。

对于 tet：

\[ J=\det F. \]

如果定义 inversion barrier：

\[ B_J(J)\rightarrow+\infty \qquad (J\rightarrow0^+), \]

它会让优化器产生“远离 \(J=0\)”的方向。

但如果 Newton/XPBD 的一次更新特别大：

\[ J=0.5 \quad\xrightarrow{\Delta x}\quad J=-0.3, \]

仅仅存在 barrier 并不自动意味着离散迭代绝不会跨过 \(J=0\)。

IPC 在碰撞问题上解决的正是这一层：

\[ \boxed{ \text{Barrier负责形成正确的排斥趋势} + \text{CCD负责不让有限步长跨越奇异边界} } \]

这对软体求解器设计有一个很重要的启发：

如果你的目标是建立真正的

\[ J>0 \]

hard invariant，那么单纯把 \(J\)-barrier 调得越来越硬未必是最漂亮的方案。

更系统的结构可能是：

\[ \underbrace{B_J(J)}_{\text{改变求解方向}} + \underbrace{\text{step-size / line-search feasibility}}_{\text{禁止跨越 }J=0}. \]

所以你刚才抓到的点很关键：IPC 的鲁棒性不能简单归功于 barrier。真正把“永不穿透”从软惩罚升级成几何不变量的，是 barrier + CCD/feasible line search 的组合；其中负责最后那道合法性保证的，确实是 CCD。
